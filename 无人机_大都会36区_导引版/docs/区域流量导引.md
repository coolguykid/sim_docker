# 区域流量导引

本版在大都会 36 区、6 层的双层 Dijkstra 上增加了拥堵导引。沿用《系统模型》的区域与航层建模，空域共有 216 个单元格。导引默认关闭。原参数配置面板中的「区域流量导引」可以开启导引、记录对照数据和调整参数。

## 导引怎样影响航线

1. 每隔一个导引周期，对正在飞行的无人机按所在区域和最接近的航层计数。用目的地区域与每个合法相邻区域的方向余弦算意愿矩阵 `Q`。并列方向均分。同一目标区域的无人机归入本区域意愿。实际管道或匝道能连通的方向才可参与优化。
2. 用上次策略预测下个周期的密度。首次使用由 `Q` 分摊到合法航层后的概率。预测达到动态阈值 `(1 − γ) × 当前密度 + γ × ρmax` 时，求解新的 `P`。优化同时考虑预测密度的均衡程度与对飞行意愿的偏离，并约束行概率和、密度上限、相邻两次已发布策略的概率变化和可选通行量上限。
3. 用 Markov 转移推演候选策略。如果某处可能超载，提高该单元格的惩罚并再求解。在规定轮数内无法得到满足条件的候选时，继续使用原策略。首次求解失败时，继续按普通双层 Dijkstra 规划。
4. 把跨区或换层边的规划代价更新为 `长度 ÷ 限速 − 导引权重 × ln(max(执行概率, 0.000001))`。概率低的通道更贵，仍可通行。这笔代价只用于选路。几何、限速、实际飞行时长以及连续避碰认证仍由现有仿真执行。区域摘要、区域内详细地图和终点入口代价使用同一策略版本。

每条任务在规划时锁定策略版本。后续的新任务可使用新策略，已规划的任务包括已预约起飞的无人机会继续执行已认证轨迹。当前集成面向程序生成的大都会和默认的 `certified_journey` 引擎。三种寻路模式均可使用，机载模式继续通过 Ray 加载当前区域详细地图。

## 参数与运行

在 Windows PowerShell 中执行。

```powershell
Set-Location -LiteralPath 'D:\无人机_大都会36区_导引版'
& 'D:\Anaconda3\envs\hxy2\python.exe' -B main.py
```

示例配置只生成 8 架，并调低了容量换算系数以复现拥堵导引。命令行参数覆盖配置文件中同名参数。

```powershell
& 'D:\Anaconda3\envs\hxy2\python.exe' -B main.py --config configs/guidance_smoke.json --guidance --guidance-gamma 0.04 --guidance-edge-penalty-seconds 60
& 'D:\Anaconda3\envs\hxy2\python.exe' -B main.py --config configs/guidance_smoke.json --no-guidance --guidance-evaluate
& 'D:\Anaconda3\envs\hxy2\python.exe' -B main.py --help
```

| JSON 中 `guidance` 的字段 | 默认值 | 含义 |
| --- | ---: | --- |
| `enabled` | false | 开启拥堵事件触发、求解和寻路权重更新 |
| `evaluate` | false | 记录采样指标，可独立用于对照组 |
| `sample_interval_seconds` | 30 | 采样及导引周期，单位为物理秒 |
| `density_limit` | 1.0 | 模型密度上限 ρmax |
| `capacity_scale` | 1.0 | 标称容量的换算系数，调小后同等流量更容易触发 |
| `gamma` | 0.5 | CBF 衰减率，调小可使接近上限时更早触发 |
| `balance_weight` | 10.0 | 密度均衡权重 λ1 |
| `intention_weight` | 1.0 | 飞行意愿权重 λ2 |
| `max_probability_change` | 0.25 | 两次已发布策略之间的单项概率最大变化量 |
| `deviation_rate` | 0.0 | 执行偏移率 α |
| `rollout_steps` | 3 | 马尔可夫推演步数 |
| `refinement_rounds` | 3 | 一次触发最多求解多少轮 |
| `overload_penalty` | 2.0 | 推演发现超载时，对应单元格惩罚的乘数 Γ |
| `edge_penalty_seconds` | 15.0 | 概率换算为边代价时的权重 |

容量以区域内实际管道长度、车道数和各层安全间距估算。无管道的传递单元格至少保留一个计数槽。概率模型可以用原单元格停留选项表达未转移的流量，仿真飞行仍由原来的航线与预约控制。单步密度预测保守地累加从其他格进入的预计数量。推演时按概率守恒搬运人口。偏移质量均匀分给其他合法选项，同时用于推演和寻路代价。实际选路由确定性的 Dijkstra 决定，观测流量可以与模型概率不同。

启用求解使用稀疏凸二次规划求解器 OSQP。项目依赖已更新，复现旧 Python 3.9 环境时可使用 `requirements-py39-hxy2.txt`。[OSQP Python 接口](https://osqp.org/docs/interfaces/python.html)

## 效果评估接口

每次运行的输出目录含 `summary.json`。开启求解或采样后，`guidance` 字段包含触发次数、发布次数、拒绝次数、采用导引权重的任务数、实测峰值密度、平均密度方差和超限采样占比。`arrivals.ndjson` 中的 `guidance_cost_revision` 可定位每架无人机使用的权重版本。版本 0 使用基础代价。

在 Python 里可用 `MetropolisSession.guidance_report()` 读取相同统计，也可设置 `session.guidance.on_sample = callback` 获取每次的时间、单元格、观测计数、预测密度、触发阈值、`Q`、`P`、求解结果和版本。需要接入数字孪生的通行反馈时，`session.guidance.transfer_feedback` 可接受候选 `P` 并返回 `{(来源单元格, 目标单元格): 每秒允许通过架数}`。程序把该速率乘以导引周期，再用于下一轮概率约束。

```python
import json
from pathlib import Path
from uav_sim.guidance import compare_guidance_runs

baseline = json.loads(Path(baseline_summary_path).read_text(encoding="utf-8"))
guided = json.loads(Path(guided_summary_path).read_text(encoding="utf-8"))
delta = compare_guidance_runs(baseline, guided)
```

比较时两组使用相同空域、需求、随机种子、终点、步长和采样参数。对照组关闭导引并开启采样。接口返回密度、到达数、飞行时长、地面等待及安全违规的原值和差值。平均密度方差越低表示观测流量在各单元格之间更均匀，结合飞行耗时与到达数可判断是否划算。

## 小规模验证

完整测试套件通过 563 项，另有 25 条 Qt 依赖弃用警告。

使用上面的示例配置，对三种寻路模式各运行 1 秒和 0.1 秒两档。每组 8 架全部到达，位置误差为 0 米，碰撞和安全违规为 0。六组逐架区域序列、物理到达时间和策略版本一致。两组机载测试由独立 Ray 进程运行，两种按区模式各核验了 108 次区域进入。

另外用命令行在集中式按区模式做导引开关对照。两组均完成 8 架。开启导引后，发布 77 次策略，6 架任务使用了导引权重，其中 2 架经过的区域序列发生变化。超限的单元格采样由 12 次降至 8 次，平均飞行时间由 1057.47 秒增至 1193.82 秒，平均地面等待由 12.81 秒降至 2.12 秒。数字只描述此处调低容量的小场景。

本次运行生成的结果位于 `artifacts/guidance_verification/`。其中 `smoke_matrix.json` 记录六组仿真，`comparison.json` 记录导引前后的对照。
