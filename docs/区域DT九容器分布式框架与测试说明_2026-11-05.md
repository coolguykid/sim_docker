# 区域 DT 九容器分布式框架与测试说明

更新时间：2026-11-05

## 1. 当前完成状态

当前已经从“单进程内创建九个 RegionWorker”改为真实的 Docker 间分布式推演：

- 9 个区域 DT 容器，每个容器包含独立 PostgreSQL/TimescaleDB、区域服务和单区域仿真会话。
- 1 个独立 `simulation-coordinator` 容器，负责统一仿真时钟、步长屏障、跨区事件路由和结果汇总。
- 每个区域只加载、规划和推进本区域路网中的 UAV。
- UAV 到达共享全局节点时由源区域产生移交事件，经协调器通过 HTTP 投递到目标区域。
- 目标区域收到事件后才建立本地 UAV、执行本区规划，并从下一个统一仿真步继续推进。
- 各区域按 1 秒基础步长采集状态，按 30 秒滑动窗口、5 秒更新间隔计算路段统计。

已经完成一架 UAV 从区域 1 到区域 9 的真实跨容器验证。实际移交链为：

```text
1 -> 2 -> 3 -> 4 -> 3 -> 2 -> 8 -> 9
```

共发生 7 次 HTTP 跨容器移交，所有区域最终均完成 1500 个统一步长，无规划失败、无待处理移交事件。

### 2.1 中心 DT

中心 DT 后续负责：

- 生成九区域导引策略。
- 提交推演任务。
- 接收推演统计和评价结果。
- 决定是否调用航路调整并再次推演。

中心 DT 不负责逐秒调用九个区域，也不直接转发 UAV 移交事件。

### 2.2 仿真协调器

协调器是独立容器，不属于某一个区域。它负责：

- 建立九区域推演任务。
- 同时向九个区域发送同一个 `step_index` 和 `sim_time`。
- 等待九个区域全部完成当前步。
- 汇总 UAV 帧和区域统计。
- 将源区域产生的移交事件投递到目标区域。
- 等目标区域确认接收后才进入下一步。
- 输出全局帧、统计和移交 CSV。

协调器不推进 UAV，也不执行区域内航迹规划。

### 2.3 区域 DT 容器

每个区域容器负责：

- 从本容器数据库加载本区域路网和 UAV 快照。
- 保存本区域有状态仿真会话。
- 根据本区域导引选择出口区域和入口层。
- 只规划本区域内的路径。
- 推进本区域 UAV、执行避让和加减速规则。
- 产生出区事件或接收入区事件。
- 统计本区域 Pipe/Ramp 交通指标。

区域容器不能读取或直接修改其他区域容器中的 UAV。

## 3. 统一步长与跨区时序

当前内部步长固定为 `dt=1s`，采用严格同步屏障。

```text
协调器发送 step(t) 给全部区域
        ↓
九区域并行推进 [t,t+1]
        ↓
九区域分别返回 t+1 帧、统计和 outbound_handoffs
        ↓
协调器等待九个区域全部返回
        ↓
协调器按 to_region 分组并投递移交事件
        ↓
目标区域把事件放入待接收队列并确认
        ↓
协调器开始 step(t+1)
```

目标区域在执行下一步之前调用 `_accept_due_handoffs()`：

1. 在 Portal 对应入口 Edge 创建 UAV。
2. 恢复速度、加速度、目的地和 `handoff_epoch`。
3. 根据目标区域导引规划本区域路径。
4. 从当前统一步开始推进。

当前 Python 规则不消费步内剩余时间，移交发生在步末，因此：

```text
crossing_time = t + 1
remaining_step_time = 0
```

## 4. Portal 与移交事件

Portal 仍由数据库共享全局节点定义：

- 源区域节点 `boundary_role=2`。
- 目标区域同一 `node_id` 节点 `boundary_role=1`。
- 两侧 `region_ids` 包含源、目标区域。
- 坐标一致。
- 源区域存在到该节点的开放有向入边。
- 目标区域存在从该节点出发的开放有向出边。

协调器从九区域数据构建 Portal 目录，初始化时只把本区域出口 Portal 下发给对应区域。

移交事件主要字段：

```json
{
  "event_id": "distributed_1_to_9_004:1:7",
  "run_id": "distributed_1_to_9_004",
  "uav_id": 1,
  "handoff_epoch": 7,
  "from_region": 8,
  "to_region": 9,
  "boundary_node_id": 2876,
  "crossing_time": 1478.0,
  "remaining_step_time": 0.0,
  "speed": 50.0,
  "acceleration": 0.0,
  "payload": {
    "entry_edge": {"edge_type": "pipe", "edge_id": 1},
    "mission": {}
  }
}
```

`event_id` 和 `handoff_epoch` 用于幂等去重。目标区域不会重复插入同一事件。

## 5. 区域 DT 服务相关目录和源码

### 5.1 `simulation_engine/`

该目录是从“无人机仅算法”中抽取出来的区域 DT 引擎适配层。底层仍复用原算法项目中的 `DatabaseRegionEnv`、`DatabaseRegionalUAV` 和 `RegionWorker`，但不再使用单进程九区域协调器。

#### `simulation_engine/local_session.py`

核心类：`LocalSimulationSession`

| 函数 | 作用 |
| --- | --- |
| `__init__(config)` | 根据本区域路网、Portal、导引和初始 UAV 创建有状态会话 |
| `_insert_initial(mission)` | 插入初始快照中的本区域 UAV |
| `queue_handoffs(events)` | 幂等暂存协调器投递的入区事件 |
| `_accept_due_handoffs()` | 在当前步开始前接收入区 UAV，并在目标区域规划 |
| `_assigned_transfer(uav, layer)` | 按导引比例、随机种子、UAV ID 和 epoch 分配目标区域/层 |
| `_plan(uav)` | 仅使用本区 `DatabaseRegionEnv` 规划本地目的地或出口 Portal |
| `step(step_index, sim_time)` | 校验统一时钟、接收入区事件、推进一秒、产生出区事件和统计 |
| `_frame()` | 输出当前区域 UAV 帧 |
| `summary()` | 输出会话步号、仿真时间、UAV 状态和失败信息 |

#### `simulation_engine/statistics.py`

核心类：`EdgeStatisticsTracker`

| 函数 | 作用 |
| --- | --- |
| `observe(...)` | 每个基础步采集路段 UAV 数量、速度和 Edge 转换事件 |
| `snapshot(...)` | 每 5 秒生成一次 30 秒滑动窗口结果 |

当前输出指标：

- 瞬时 UAV 数量。
- 窗口平均 UAV 数量。
- 瞬时空间平均速度。
- 窗口 UAV-时间加权空间平均速度。
- 窗口流入量、流出量。
- 流入率、流出率，单位架/min。
- 瞬时密度，单位架/km。
- 窗口平均密度。
- 平均每 Lane 密度。
- 窗口预热标志。

### 5.2 `region_service/`

#### `app.py`

区域服务 FastAPI 入口，同时保留原有工作流接口和新增分布式接口。

新增接口：

| 接口 | 作用 |
| --- | --- |
| `POST /api/v1/distributed/runs/init` | 初始化本区域有状态会话 |
| `POST /api/v1/distributed/runs/{run_id}/handoffs` | 接收协调器投递的入区事件 |
| `POST /api/v1/distributed/runs/{run_id}/step` | 推进一个统一仿真步 |
| `GET /api/v1/distributed/runs/{run_id}` | 查询本区域会话状态 |
| `POST /api/v1/distributed/runs/{run_id}/finalize` | 结束会话并返回摘要 |

#### `distributed_runtime.py`

管理当前容器内的 `LocalSimulationSession`。

| 函数 | 作用 |
| --- | --- |
| `initialize_session(payload)` | 从数据库加载快照并创建本区域会话 |
| `queue_handoffs(run_id, events)` | 将移交事件交给指定会话 |
| `advance(run_id, step_index, sim_time)` | 推进指定会话一个步长 |
| `get_summary(run_id)` | 查询会话摘要 |
| `finalize(run_id)` | 删除内存会话并返回最终摘要 |

当前会话放在进程内存 `_sessions` 中，同一容器内通过锁保护。

#### `snapshot_loader.py`

`load_snapshot(request)` 使用只读、可重复读事务加载：

- `node_info`
- `pipe_info` 与指定时刻最新 `pipe_status`
- `ramp_info` 与指定时刻最新 `ramp_status`
- `lane_info`
- 指定时刻每架 UAV 最新 `uav_data` 和 `uav_info`

数据库中的 `speed_limit`、`d_safe` 和 `max_capacity` 会转换为引擎直接使用的字段。

#### 其他区域服务文件

| 文件 | 作用 |
| --- | --- |
| `models.py` | 原导引请求和通用移交事件模型 |
| `repository.py` | 工作流任务、事件、handoff inbox/outbox 的数据库持久化 |
| `workflow.py` | 原“快照—完整推演—评价—调整—下发”业务编排框架 |
| `engine_contract.py` | 一次性推演接口 DTO 和输出协议 |
| `integration_ports.py` | 评价、航路调整、运行系统下发等待接入接口；旧单进程九区域入口已禁用 |
| `result_sink.py` | 原工作流的帧、统计和移交结果接收端口 |

分布式推演的正式入口是协调器 `/api/v1/runs`，不是分别调用九个区域的旧 `/api/v1/guidance`。

## 10. 尚未完成与后续方向

1. 中心 DT 尚未调用协调器正式 `/api/v1/runs` 接口。
2. 正式任务应从各区域数据库 UAV 快照和中心导引构造 `uavs_by_region`、`guidance_by_region`；当前演示任务由协调器生成。
3. 严重拥堵评价策略尚未定义。
4. 航路调整算法尚未接入。
5. 达标后向运行子系统下发导引的可靠消息接口尚未接入。
6. 区域会话当前在内存中，容器重启后不能恢复；后续需要会话检查点或事件回放。
7. 协调器当前是单实例，后续 36 区域生产部署需增加持久化、主备或租约机制。
8. 当前 HTTP 足以完成框架和功能验证；大规模 UAV 压测后再决定是否切换 NATS、Kafka 或 gRPC。
9. 全局输出当前为 JSONL/CSV，尚未接到现有前端实时帧接口。
10. 当前统计已经产生，但拥堵阈值、容量利用率和持续时间判断尚未实现。
