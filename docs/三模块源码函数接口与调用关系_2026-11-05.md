# coordinator_service、region_service、simulation_engine 源码说明

本文对应 `D:\shuo\sim_docker` 当前源码，说明每个文件、类和函数的职责、输入、
输出、副作用、直接调用者以及当前是否进入正式九容器执行链。

## 1. 三个模块的边界

```text
中心DT/测试客户端
  -> POST region_service /api/v1/guidance

region_service
  -> 保存导引任务
  -> 加载本区数据库快照
  -> 创建 simulation_engine.LocalSimulationSession
  -> 向 coordinator_service 注册本区已就绪
  -> 本区评价、调整、提交和下发

coordinator_service
  -> 同时调用九个 region_service 的 /step
  -> 收集 outbound_handoffs
  -> 按 to_region 调用目标 region_service 的 /handoffs
  -> 不读取路网/UAV，不规划，不评价拥堵

simulation_engine（运行在每个区域容器内）
  -> 构造本区图
  -> 本区规划、避障和推进
  -> 生成/接收 handoff
  -> 输出本区帧与统计 CSV
```

当前关键调用链：

```text
receive_guidance()
  -> enqueue_request()
  -> worker_loop()
  -> execute()
  -> run_workflow()
       -> load_snapshot()
       -> initialize_session()
            -> LocalSimulationSession(...)
       -> register_attempt()
            -> coordinator.register_region()
                 -> drive_attempt()
                      -> region.step_distributed_run()
                           -> distributed_runtime.advance()
                                -> LocalSimulationSession.step()
                      -> region.submit_distributed_handoffs()
                           -> LocalSimulationSession.queue_handoffs()
       -> get_result()
       -> evaluate_statistics()
       -> report_decision()
       -> commit_to_database()/invoke_network_adjustment()/dispatch_guidance()
```

## 2. coordinator_service

### 2.1 `coordinator_service/app.py`

这是独立协调器容器的全部业务代码。状态保存在进程内的 `ATTEMPTS`、`TASKS`，
协调器重启后不会恢复正在执行的 attempt。

#### 全局对象

| 对象 | 类型 | 作用 |
| --- | --- | --- |
| `ATTEMPTS` | `dict[(run_id, attempt_id), dict]` | 保存同步任务、区域注册地址、步数、handoff计数和评价结论 |
| `TASKS` | `dict[(run_id, attempt_id), asyncio.Task]` | 保存 `drive_attempt()` 后台任务引用 |
| `app` | `FastAPI` | 协调器 HTTP 应用 |

#### `_key(run_id, attempt_id)`

- 输入：`run_id` 可转字符串，`attempt_id` 可转整数。
- 输出：`(str(run_id), int(attempt_id))`。
- 调用者：`register_region()`、`get_attempt()`、`report_decision()`。
- 作用：统一内存字典键格式。

#### `_post_sync(url, payload)`

- 输入：目标区域 URL；可 JSON 序列化的字典。
- 输出：目标 HTTP 接口返回的 JSON 字典。
- 异常：目标返回非 2xx 时抛 `RuntimeError`，包含 HTTP 状态和响应正文。
- 调用者：仅 `_post()`。
- 下游：区域容器 `/step` 和 `/handoffs` 接口。

#### `_post(url, payload)`

- 输入/输出：与 `_post_sync()` 相同。
- 实现：用 `asyncio.to_thread()` 执行阻塞 HTTP 请求。
- 调用者：`drive_attempt()`。
- 作用：允许协调器并发调用九个区域，不阻塞 asyncio 事件循环。

#### `public_attempt(record)`

- 输入：协调器内部 attempt 字典。
- 输出：公开状态字典，字段包括：

```text
run_id, attempt_id, status, expected_region_ids, registered_region_ids,
completed_steps, sim_time, handoff_count, handoff_pairs, decisions,
collective_decision, error, created_at, started_at, finished_at
```

- 调用者：`register_region()`、`get_attempt()`、`report_decision()`。
- 作用：不向外暴露区域 endpoint、后台任务和 traceback 等内部数据。

#### `drive_attempt(record)`

- 输入：已经包含全部参与区域注册地址的 attempt 字典。
- 输出：无函数返回值；持续修改 `record`。
- 调用者：`register_region()` 在全部区域完成注册时通过
  `asyncio.create_task()` 启动。
- 每一步执行：
  1. 并发 POST 所有区域的 `/step`，输入为
     `{"step_index": n, "sim_time": n*dt}`。
  2. 收集各区返回的 `outbound_handoffs`。
  3. 按 `to_region` 分组。
  4. POST 到目标区域 `/handoffs`。
  5. 更新 `handoff_count`、`handoff_pairs`、`completed_steps`、`sim_time`。
- 正常终态：`status=simulation_completed`。
- 异常终态：`status=failed`，写入 `error/traceback/finished_at`。
- 边界：它不查看 UAV 内容，不修改事件，不执行规划。

#### `health()` — `GET /health`

- 输入：无。
- 输出：

```json
{"status":"ready","role":"step-barrier-and-handoff-relay"}
```

- 调用者：Docker healthcheck、运维检查。

#### `register_region(run_id, attempt_id, region_id, payload)`

HTTP：`POST /api/v1/runs/{run_id}/attempts/{attempt_id}/regions/{region_id}/register`

- 调用者：每个区域的 `workflow.run_workflow()`，经
  `coordinator_client.register_attempt()` 调用。
- 输入路径：`run_id/attempt_id/region_id`。
- 输入 JSON：

```json
{
  "run_id":"run_001",
  "attempt_id":0,
  "region_id":1,
  "endpoint":"http://region-dt-01:8080",
  "expected_region_ids":[1,2,3,4,5,6,7,8,9],
  "horizon_seconds":300,
  "step_seconds":1.0
}
```

- 输出：`public_attempt(record)`，HTTP 202。
- 副作用：首次注册创建 attempt；后续注册写入区域 endpoint；全部区域就绪时启动
  `drive_attempt()`。
- 校验：所有区域声明的 `expected_region_ids` 必须一致，注册区域必须在列表中。

#### `get_attempt(run_id, attempt_id)`

HTTP：`GET /api/v1/runs/{run_id}/attempts/{attempt_id}`

- 调用者：区域的 `coordinator_client.wait_for_status()`、测试/运维客户端。
- 输出：`public_attempt(record)`。
- 不存在：HTTP 404。

#### `report_decision(run_id, attempt_id, region_id, payload)`

HTTP：`POST /api/v1/runs/{run_id}/attempts/{attempt_id}/regions/{region_id}/decision`

- 调用者：各区域 `run_workflow()` 经 `coordinator_client.report_decision()`。
- 输入 JSON：`{"decision":"acceptable"}` 或
  `{"decision":"adjustment_required"}`。
- 输出：更新后的公开 attempt，HTTP 202。
- 副作用：收集各区本地评价；全部返回后生成：
  - 全部 `acceptable`：`collective_decision=acceptable`。
  - 任一区域需调整：`collective_decision=rerun_required`。
- 注意：这里只同步结论，不计算交通指标，也不替区域做业务判断。

## 3. region_service

每个区域 Docker 内都有一份 region_service，但 `REGION_ID`、数据库和输出目录不同。

### 3.1 `region_service/models.py`

#### `GuidanceTransfer`

单条层间导引规则：

```json
{
  "source_layer":2,
  "target_region_id":8,
  "target_layer":3,
  "proportion":0.4
}
```

约束：层号非负、目标区域大于0、比例在 `(0,1]`。

#### `GuidanceRequest`

`POST /api/v1/guidance` 的请求模型。主要字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `run_id` | string | 本次业务任务标识 |
| `attempt_id` | int | 基础尝试编号 |
| `region_id` | int | 接收该请求的区域 |
| `snapshot_time` | datetime | 数据库快照截止时间 |
| `topology_version` | int | 路网版本 |
| `horizon_seconds` | int | 推演时长 |
| `step_seconds` | float | 公共步长，当前引擎只接受1s |
| `transfers` | list | 本区层转移比例 |
| `participating_region_ids` | list[int] | 本次同步参与区域 |
| `simulation_uavs` | list[dict] | 测试/外部直接提供 UAV；为空时读取数据库 |
| `congestion_policy` | dict | 拥堵阈值 |
| `topology_adjustments` | dict | 初始临时路网调整 |
| `max_adjustment_rounds` | int | 最大重推轮数 |

#### `GuidanceRequest.validate_transfer_proportions()`

- 调用者：Pydantic 在构造 `GuidanceRequest` 时自动调用。
- 输入：模型自身。
- 输出：校验通过返回自身。
- 校验：每个 `source_layer` 下比例和必须为1；当前区域必须属于参与区域；参与区域
  不得重复。

#### `HandoffInput`

旧持久化 handoff 接口 `/api/v1/handoffs` 的模型，包含事件编号、UAV、epoch、来源/
目标区域、共享节点、穿越时间、剩余步长和 payload。当前同步推演使用内存
`/distributed/.../handoffs`，不使用这个 Pydantic 模型。

### 3.2 `region_service/app.py`

#### 全局对象

- `queue`：区域业务任务队列，元素为 `(run_id, attempt_id)`。
- `worker_task`：运行 `worker_loop()` 的 asyncio 后台任务。
- `app`：区域 FastAPI 应用。

#### `public_task(row)`

- 输入：数据库 `region_dt_simulation` 一行字典。
- 输出：对外任务摘要，包含标识、状态、快照摘要、结果摘要、错误和时间字段。
- 调用者：`simulation_status()`。

#### `execute(run_id, attempt_id)`

- 输入：任务键。
- 输出：无。
- 调用者：`worker_loop()` 通过线程执行。
- 下游：`repository.get_task()`、`workflow.run_workflow()`。

#### `worker_loop()`

- 输入：无；永久消费全局 `queue`。
- 输出：无，直到服务关闭取消。
- 调用者：`lifespan()` 创建后台任务。
- 作用：串行执行本区域业务任务，避免同一区域多个 workflow 同时争用状态。

#### `lifespan(_app)`

- 调用者：FastAPI 启动/关闭机制。
- 启动阶段：建控制表；恢复数据库中 `queued` 任务；启动 `worker_loop()`。
- 关闭阶段：取消并等待后台 worker。

#### `health()` — `GET /health`

- 调用者：Docker healthcheck、运维。
- 输出：数据库状态、区域编号和模拟器状态。
- 状态可能为：`busy`、`waiting_guidance` 或具体 `waiting_*` 集成状态。

#### `receive_guidance(request, response)` — `POST /api/v1/guidance`

- 调用者：中心 DT；测试脚本也通过同一正式入口调用。
- 输入：`GuidanceRequest` JSON。
- 输出：`accepted/created/region_id/run_id/attempt_id/status`。
- 副作用：调用 `enqueue_request()` 持久化；新任务加入内存队列。
- 幂等：相同键和相同内容返回 HTTP 200；相同键但内容不同返回409。

#### `simulation_status()` — `GET /api/v1/simulations/{run_id}/attempts/{attempt_id}`

- 调用者：测试、前端、运维。
- 输出：`public_task()`。

#### `simulation_handoffs()` — `GET .../handoffs`

- 输出：数据库 `handoff_outbox` 事件列表。
- 当前状态：预留/旧链路。当前分布式 session 的 handoff 直接由协调器转发，并未调用
  `store_outbox()`，因此该接口不代表当前内存转发事件全集。

#### `simulation_events()` — `GET .../events`

- 输出：该任务按序排列的业务事件，如 `snapshotting`、`regional_session_ready`、
  `evaluated`、`waiting_guidance_dispatch`。
- 调用者：测试报告、诊断工具。

#### `resume_simulation()` — `POST .../resume`

- 输入：路径任务键。
- 输出：接受恢复的任务标识和 `queued` 状态。
- 调用者：人工/外部恢复客户端。
- 仅允许恢复 `failed` 或 `waiting_*`，随后重新进入区域 worker 队列。

#### `receive_handoff()` — `POST /api/v1/handoffs`

- 输入：`HandoffInput`。
- 输出：是否首次接收、事件ID和状态。
- 副作用：写 `handoff_inbox`，按 event_id 幂等。
- 当前状态：旧的持久化阶段接口；同步九容器推进不调用它。

#### `submit_distributed_handoffs()` — `POST /api/v1/distributed/runs/.../handoffs`

- 调用者：`coordinator_service.drive_attempt()`。
- 输入：`{"events":[handoff,...]}`。
- 输出：`{"accepted":true,"summary": session.summary()}`。
- 下游：`distributed_runtime.queue_handoffs()`。
- 404：session 未创建；422：目标区域不匹配等事件错误。

#### `step_distributed_run()` — `POST /api/v1/distributed/runs/.../step`

- 调用者：每个统一步由 `coordinator_service.drive_attempt()` 调用。
- 输入：`step_index` 和 `sim_time`。
- 输出：`LocalSimulationSession.step()` 的完整步结果，包含帧、统计和出区事件。
- 409：步号或时间不连续。

#### `get_distributed_run()` — `GET /api/v1/distributed/runs/...`

- 输出：当前内存 session 摘要。
- 调用者：诊断工具；正式 workflow 不依赖它。

#### `get_distributed_result()` — `GET /api/v1/distributed/runs/.../result`

- 输出：当前内存 session 的汇总、统计历史和 CSV 路径。
- 调用者：诊断工具；workflow 在同容器内直接调用 `distributed_runtime.get_result()`。

### 3.3 `region_service/coordinator_client.py`

#### `_request(method, url, payload=None)`

- 输入：HTTP 方法、URL、可选 JSON。
- 输出：解码后的 JSON。
- 调用者：本文件其余四个函数。
- 异常：协调器非2xx时抛 `RuntimeError`。

#### `register_attempt(base_url, payload)`

- 输入：协调器地址和区域注册字典。
- 输出：协调器公开 attempt。
- 调用者：`workflow.run_workflow()`。

#### `get_attempt(base_url, run_id, attempt_id)`

- 输出：协调器公开 attempt。
- 调用者：`wait_for_status()`。

#### `wait_for_status(..., terminal, poll_seconds=0.2)`

- 输入：协调器地址、任务键、终态集合、轮询间隔。
- 输出：首次进入指定终态时的 attempt 字典。
- 调用者：`run_workflow()`；分别等待推演结束和全部区域评价结束。
- 注意：当前无总超时，协调器或其他区域永久不返回时会持续等待。

#### `report_decision(base_url, payload)`

- 输入：`run_id/attempt_id/region_id/decision`。
- 输出：协调器更新后的 attempt。
- 调用者：`run_workflow()`。

### 3.4 `region_service/distributed_runtime.py`

该文件管理本区域进程内的有状态 session。`_sessions` 的键为
`(run_id, attempt_id)`，`RLock` 保证 step、handoff 和查询不会同时修改同一 session。

#### `_key(run_id, attempt_id)`

统一 session 键。由本文件全部公开函数调用。

#### `initialize_session(config)`

- 输入：包含路网、UAV、导引、统计参数和输出目录的 session config。
- 输出：`(session.summary(), created_bool)`。
- 调用者：`workflow.run_workflow()`。
- 下游：`LocalSimulationSession(config)`。
- 幂等：相同键已存在时返回现有摘要，不重复创建。

#### `queue_handoffs(run_id, attempt_id, events)`

- 输入：任务键和事件数组。
- 输出：session 最新摘要。
- 调用者：区域 HTTP `submit_distributed_handoffs()`。
- 下游：`LocalSimulationSession.queue_handoffs()`。

#### `advance(run_id, attempt_id, step_index, sim_time)`

- 输入：任务键、公共步号和公共时间。
- 输出：单步结果字典。
- 调用者：区域 HTTP `step_distributed_run()`。
- 下游：`LocalSimulationSession.step()`。

#### `get_summary()` / `get_result()`

- 输入：任务键。
- 输出：不存在返回 `None`；存在分别返回 session 摘要/完整结果。
- 调用者：区域查询接口；`get_result()` 还由 `workflow.run_workflow()` 调用。

#### `finalize(run_id, attempt_id)`

- 输出：关闭前的最终结果。
- 副作用：从 `_sessions` 删除 session，并关闭 CSV 文件。
- 调用者：`workflow.run_workflow()` 完成本轮评价后。

### 3.5 `region_service/repository.py`

#### `dsn()`

- 输出：优先返回 `REGION_DATABASE_URL`，否则根据本容器 PostgreSQL 环境变量构造 DSN。
- 调用者：`connection()`。

#### `connection(row_factory=None)`

- contextmanager，输出 psycopg 连接。
- 调用者：repository、snapshot_loader、topology_adjustments 中所有数据库函数。
- 离开 `with` 时提交成功事务或回滚异常事务并关闭连接。

#### `initialize_control_schema()`

- 调用者：`app.lifespan()`。
- 输出：无。
- 副作用：创建 `region_dt_simulation`、`handoff_outbox`、`handoff_inbox`、
  `region_dt_workflow_event`；将服务重启前仍处于活动状态的任务标为失败。

#### `database_ready()`

- 输出：数据库 `SELECT 1` 是否成功。
- 调用者：`app.health()`。

#### `has_active_task()`

- 输出：本区域是否存在 queued/推演中任务。
- 调用者：`app.health()`。

#### `waiting_integration_status()`

- 输出：最近的 `waiting_*` 状态或 `None`。
- 调用者：`app.health()`。

#### `enqueue_request(payload)`

- 输入：导引请求字典。
- 输出：`(created_bool, existing_or_status_dict)`。
- 调用者：`app.receive_guidance()`。
- 副作用：新请求写入 `region_dt_simulation`。
- 幂等键：`run_id + attempt_id + region_id`；相同键不同内容抛 `ValueError`。

#### `list_queued_keys()`

- 输出：按创建时间排列的 `(run_id, attempt_id)`。
- 调用者：`app.lifespan()` 恢复尚未执行的任务。

#### `append_workflow_event(...)`

- 输入：任务键、事件类型和 payload。
- 输出：无；写 `region_dt_workflow_event`。
- 调用者：`workflow.run_workflow()` 各阶段。

#### `list_workflow_events(...)`

- 输出：按 `event_seq` 排列的事件字典数组。
- 调用者：`app.simulation_events()`。

#### `requeue_task(...)`

- 输出：是否成功把一行 waiting/failed 任务改回 queued。
- 调用者：`app.resume_simulation()`。

#### `get_task(...)`

- 输出：完整任务行字典或 `None`。
- 调用者：`app.execute()`、`app.simulation_status()`。

#### `mark_status(..., status, **fields)`

- 输入：任务键、新状态，可选快照摘要、结果摘要、错误文本。
- 输出：无；更新数据库任务行和相应时间字段。
- 调用者：`workflow.run_workflow()`。

#### `store_outbox(event)`

- 输入：handoff 字典。
- 输出：无；按 event_id 幂等写 outbox。
- 当前调用者：仅预留的 `RepositoryOutputSink.on_handoff()`；当前同步推演未调用。

#### `store_inbox(event)`

- 输入：handoff 字典。
- 输出：首次插入返回 `True`，重复事件返回 `False`。
- 调用者：旧接口 `app.receive_handoff()`。

#### `list_outbox(run_id, attempt_id)`

- 输出：按穿越时间排序的 outbox 事件。
- 调用者：`app.simulation_handoffs()`。

### 3.6 `region_service/snapshot_loader.py`

#### `_fetch_all(conn, query, params)`

- 输入：数据库连接、SQL、参数。
- 输出：字典列表。
- 调用者：`load_snapshot()`。

#### `load_snapshot(request)`

- 输入：至少包含 `topology_version`、`snapshot_time` 的导引请求字典。
- 输出：

```text
{
  region_id, topology_version, snapshot_time,
  network: {nodes, pipes, ramps, lanes},
  uavs: [最新UAV状态...]
}
```

- 调用者：`workflow.run_workflow()`，每个业务任务只加载一次。
- 事务：`REPEATABLE READ, READ ONLY`。
- 路网状态：选取 `snapshot_time` 之前最新 pipe/ramp status。
- UAV：每个 `uav_id` 选取截止快照时刻的最新一条，并连接起终点信息。
- 边界：只做数据库到 DTO 映射，不构图、不规划、不推进。

#### `snapshot_summary(snapshot)`

- 输出：快照时间、版本及 node/pipe/ramp/lane/UAV 数量。
- 调用者：`workflow.run_workflow()`。

### 3.7 `region_service/topology_adjustments.py`

#### `merge_adjustments(current, new_values)`

- 输入：当前累计调整和新一轮调整，结构为 `pipes[]/ramps[]`。
- 输出：深拷贝合并结果；相同 pipe_id/ramp_id 以后一次字段覆盖前一次。
- 调用者：`workflow.run_workflow()` 调整轮。

#### `apply_to_snapshot(original_snapshot, adjustments)`

- 输入：第一次数据库快照、累计临时调整。
- 输出：新的深拷贝快照。
- 可调整 Pipe：`is_open/speed_limit/d_safe/max_capacity`。
- 可调整 Ramp：`is_open`。
- 调用者：每轮 `run_workflow()`。
- 重要：不写数据库，保证每轮都以同一 `original_snapshot` 为基准。

#### `commit_to_database(topology_version, effective_snapshot, adjustments)`

- 输入：版本、通过评价的有效快照、累计调整。
- 输出：`topology_changed`、变化时间和 Pipe/Ramp 数量。
- 调用者：仅在所有区域评价通过后由 `run_workflow()` 调用。
- 副作用：同一事务向 `pipe_status/ramp_status` 插入正式状态；无调整时不写库。

### 3.8 `region_service/integration_ports.py`

#### `invoke_simulation_engine(simulation_input, output_sink)`

- 当前状态：未使用的旧单次引擎接口，固定抛 `IntegrationPending`。
- 当前分布式链使用 `distributed_runtime + coordinator`，不调用它。

#### `evaluate_statistics(engine_result, request)`

- 输入：本区域完整 engine result；导引请求。
- 输出：

```json
{
  "decision":"acceptable|adjustment_required",
  "severe_congestion":[...],
  "policy":{"capacity_ratio":0.8,"speed_ratio":0.5,"duration_seconds":15}
}
```

- 调用者：`workflow.run_workflow()`。
- 判定：窗口平均数量/容量达到阈值，且空间平均速度/限速低于阈值，并持续指定时间；
  任一 `planning_failures` 也要求调整。

#### `invoke_network_adjustment(adjustment_input)`

- 预期输入：初始快照摘要、当前调整、统计和评价。
- 预期输出：新的 `pipes/ramps` 调整字典。
- 未接入算法时使用 `IntegrationPending("network_adjustment")` 表示等待状态。
- 调用者：`run_workflow()` 在需要调整且仍有剩余轮次时。

#### `dispatch_guidance(dispatch_input)`

- 预期输入：导引、评价、`topology_changed`、变化详情和累计调整。
- 预期输出：运行子系统接收回执。
- 当前状态：运行系统接口未接入，抛 `IntegrationPending("guidance_dispatch")`。
- 调用者：所有区域通过且数据库提交完成后由 `run_workflow()` 调用。

### 3.9 `region_service/workflow.py`

#### `WAITING_STATUS`

把集成组件名映射为数据库等待状态，例如 route adjustment 对应
`waiting_network_adjustment`。

#### `_uav_missions(snapshot, request)`

- 输入：数据库快照和导引请求。
- 输出：simulation_engine 接受的 UAV mission 列表。
- 规则：`simulation_uavs` 非空时优先使用；否则把数据库 `uav_data/uav_info` 行转换为
  mission。
- 调用者：`run_workflow()`。

#### `_attempt_output_dir(run_id, attempt_id)`

- 输出：`REGION_OUTPUT_DIR/<run_id>/attempt_NNN` Path。
- 调用者：`run_workflow()`。

#### `run_workflow(request)`

- 输入：已经通过 `GuidanceRequest` 校验并从数据库取回的请求字典。
- 输出：无直接返回；状态、事件、CSV 和数据库写入构成输出。
- 调用者：`app.execute()`。
- 完整流程：
  1. 状态改为 snapshotting，加载一次 `original_snapshot`。
  2. 转换 UAV missions。
  3. 每轮把累计调整应用到原始快照副本。
  4. 创建本区 LocalSimulationSession。
  5. 向协调器注册并等待统一推演结束。
  6. 读取本区统计，独立评价并上报结论。
  7. 等待所有区域形成 collective decision。
  8. 关闭当前 session。
  9. 全部通过：提交路网状态并下发导引。
  10. 需要重跑：本区按需调用航路调整，进入下一 attempt。
- `IntegrationPending`：转换为相应 `waiting_*`，保留任务供未来 resume。
- 其他异常：记录 workflow event 并标记 failed。

### 3.10 `region_service/engine_contract.py`

这是未来外部仿真引擎的稳定接口定义，当前九容器内存 step 链未直接使用。

#### `IntegrationPending`

集成点未实现异常，保存 `component` 名称。由 integration_ports 抛出，由
`run_workflow()` 捕获。

#### `SimulationEngine` / `SimulationOutputSink`

Python `Protocol`：约定未来引擎提供 `simulate()`；输出接收器提供
`on_frame/on_statistics/on_handoff`。它们不产生运行时代码。

#### `build_simulation_input(request, snapshot, topology_adjustments, round_index)`

- 输出标准 `region-dt-simulation-input/v1` DTO，包含任务、路网、UAV、导引和调整。
- 当前调用者：无；保留给未来外部引擎适配层。

#### `validate_engine_result(result)`

- 校验结果为字典且含 `statistics/handoff_events/diagnostics`。
- 输出：通过校验的原字典。
- 当前调用者：无。

### 3.11 `region_service/result_sink.py`

#### `RepositoryOutputSink.__init__(request, round_index)`

保存任务信息并初始化帧、统计、handoff计数。当前正式链未实例化。

#### `on_frame(frame)` / `on_statistics(statistics)`

当前只增加计数，不保存内容。预留给未来流式引擎。

#### `on_handoff(handoff)`

补齐 run/attempt/from_region，按 event_id 去重并调用 `store_outbox()`。

#### `summary()`

输出 `frame_count/statistics_batches/handoff_count`。

当前状态：整个类是未来/旧式 streaming port，当前 LocalSimulationSession 直接写 CSV，
协调器直接转发内存事件。

## 4. simulation_engine

该包被复制进每个区域镜像，在区域容器内执行，不在协调器容器中执行。

### 4.1 `simulation_engine/__init__.py`

只导出 `LocalSimulationSession`。调用者是
`region_service.distributed_runtime`。

### 4.2 `simulation_engine/csv_output.py`

#### `RegionalCsvOutput.__init__(output_dir)`

- 输入：本轮区域输出目录。
- 输出：构造对象。
- 副作用：创建目录，覆盖创建 `uav_states.csv`、`edge_statistics.csv`，写表头。
- 调用者：`LocalSimulationSession.__init__()`。

UAV 帧字段：

```text
time,uav_id,region_id,topology_version,active,departed,arrived,edge_type,
node_id,pipe_id,ramp_id,lane_id,distance,edge_length,current_speed,x,y,z,acceleration
```

#### `write_frame(frame)`

- 输入：内部 UAV 状态字典数组。
- 输出：无。
- 转换：生命周期转 `active/departed/arrived`；pipe/ramp 转 C++ 兼容数字和ID；展开
  三维 position。
- 副作用：逐 UAV 写 CSV，每帧 flush。
- 调用者：session 初始化写 `t=0`；每次 `LocalSimulationSession.step()`。

#### `write_statistics(batch)`

- 输入：`EdgeStatisticsTracker.snapshot()` 字典或 `None`。
- 输出：无；每条 Edge 一行并 flush。
- 调用者：`LocalSimulationSession.step()`。

#### `close()`

关闭两个文件流，可重复调用。
- 调用者：`LocalSimulationSession.close()`。

### 4.3 `simulation_engine/statistics.py`

#### `EdgeStatisticsTracker.__init__(env, window_seconds=30, update_interval=5)`

- 输入：区域图环境、滑动窗口长度、输出间隔。
- 初始化：状态采样 deque、出入事件 deque、上一步 UAV→Edge 映射。
- 调用者：`LocalSimulationSession.__init__()`。

#### `_key(edge_ref)`

- 输出：`"pipe:12"` 或 `"ramp:8"`。
- 调用者：`observe()`。

#### `observe(sim_time, uavs, explicit_in=None, explicit_out=None)`

- 输入：当前时刻、区域内 UAV iterable、显式跨区流入/流出边。
- 输出：未到5秒更新点返回 `None`；到点返回 `snapshot()`。
- 统计对象：只计 `FLYING/WAITING` UAV。
- 处理：瞬时数量/速度和、相邻步 Edge 变化、窗口裁剪、跨区显式流量补充。
- 调用者：`LocalSimulationSession.step()`。

#### `snapshot(sim_time, instant_counts, instant_speed_sums)`

- 输入：当前时刻、瞬时计数和速度和。
- 输出：

```text
{time, window_seconds, warmup, edges:[
  edge_type, edge_id, length_m, lane_count,
  instant_uav_count, window_average_uav_count,
  instant_space_mean_speed, window_space_mean_speed,
  window_in_count, window_out_count,
  in_flow_per_minute, out_flow_per_minute,
  instant_density_per_km, window_density_per_km,
  window_density_per_km_lane, speed_limit, max_capacity
]}
```

- 调用者：`observe()`。

### 4.4 `simulation_engine/local_session.py`

#### `_edge_ref(value)`

- 输入：已有 `EdgeRef` 或 `{"edge_type","edge_id"}`。
- 输出：`EdgeRef`。
- 调用者：`_current_edge()`、`_plan()`。

#### `LocalSimulationSession.__init__(config)`

- 输入核心结构：

```text
run_id, attempt_id, region_id, topology_version, step_seconds,
network{nodes,pipes,ramps,lanes}, uavs[], guidance{transfers},
random_seed, statistics_window_seconds, statistics_interval_seconds, output_dir
```

- 输出：有状态 session 对象。
- 调用者：`distributed_runtime.initialize_session()`。
- 处理：只保留开放 Pipe/Ramp；构造 `DatabaseRegionEnv`；创建本区 `RegionWorker`；
  生成出口 Portal；创建统计器和 CSV；插入初始 UAV；写 `t=0` 帧。
- 限制：当前只接受 `dt=1s`。

#### `_build_local_portals()`

- 输入：隐式使用本区 env。
- 输出：Portal 对象列表。
- 规则：只处理 `boundary_type=2` 共享节点；本区进入该节点的 Edge 是出口边；
  `node.region_ids` 中除本区外的区域是目标区域。
- 调用者：session 构造函数。

#### `_lane_index(edge, external_lane_id)`

- 输入：Edge 和数据库 lane_id。
- 输出：引擎内部 lane 数组下标；找不到时使用合法下标或0。
- 调用者：`_insert_initial()`。

#### `_current_edge(mission)`

- 输入：UAV mission。
- 输出：当前 `EdgeRef`。
- 优先级：`current_edge` → edge_type+pipe/ramp ID → node_id 的第一条开放出边。
- 调用者：`_insert_initial()`。

#### `_insert_initial(mission)`

- 输入：一架初始 UAV mission。
- 输出：无。
- 处理：创建 `DatabaseRegionalUAV`、恢复位置/速度/加速度/出发步/epoch、加入
  RegionWorker、调用 `_plan()`。
- 失败：UAV 保持可见但置 `HOLDING`，并向构造函数抛出，由构造函数记录
  `planning_failures`。

#### `queue_handoffs(events)`

- 输入：协调器转发来的事件数组。
- 输出：无。
- 去重：已等待或已处理的 event_id 被忽略。
- 校验：`to_region` 必须是本区。
- 调用者：`distributed_runtime.queue_handoffs()`。

#### `_resolve_entry_edge(boundary_node_id, target_layer)`

- 输入：共享节点ID、目标层。
- 输出：目标区域本地入口 `EdgeRef`。
- 规则：优先该节点指定层的第一条开放出边；没有同层边时退化为第一条开放出边。
- 调用者：`_accept_due_handoffs()`。
- 已知不足：多候选入口尚未结合后续路径可达性选择。

#### `_accept_due_handoffs()`

- 输入：隐式读取 `pending_handoffs` 和当前 session time。
- 输出：本步接受的入口 Edge 列表，供统计流入。
- 处理：只接收 `crossing_time <= current time` 的事件；重建 UAV；恢复 mission、速度、
  加速度和 epoch；加入本区并重新 `_plan()`。
- 失败：置 `HOLDING` 并记录 planning failure，不击穿整个区域。
- 调用者：`step()`。

#### `_assigned_transfer(uav, current_layer)`

- 输入：UAV、当前层。
- 输出：选中的导引规则；该层无规则返回 `None`。
- 算法：校验比例和；对 `seed+uav_id+epoch+region_id` 做 SHA-256，形成可重复的
  `[0,1)` 数，再按累计比例选择。
- 调用者：`_plan()`。

#### `_nearest_local_destination(point)`

- 输入：三维目的坐标。
- 输出：本区距离该点最近的 Edge 和投影距离。
- 调用者：`_plan()` 在 mission 未指定 destination_edge 时。

#### `_plan(uav)`

- 输入：已存在于 `missions` 的 UAV。
- 输出：无；给 UAV 设置本区 route 和可选出口 Portal。
- 有导引：寻找目标相邻区域所有出口 Portal，计算本区到各出口路径，选择最低成本的
  可达出口。
- 无导引：认为进入最终区域，规划到 destination_edge 或最近目的坐标投影。
- 失败：抛 `ValueError`。
- 调用者：初始插入、跨区接收。

#### `step(step_index, sim_time)`

- 输入：协调器给出的当前步号和步开始时间。
- 输出：

```text
{
  region_id, attempt_id, step_index, sim_time,
  uav_frame, statistics, outbound_handoffs, planning_failures
}
```

- 调用者：`distributed_runtime.advance()`。
- 顺序：校验时间 → 接收入区事件 → RegionWorker推进 → 把到达出口的 UAV 移出并
  生成 handoff → 时间加1 → 统计 → 生成帧 → 写 CSV。
- Handoff payload 保留目标层、速度、加速度和完整 mission，使目标区域能够继续滚动规划。

#### `_frame()`

- 输出：当前仍由本区拥有的所有 UAV 内部状态数组，按 uav_id 排序。
- 调用者：构造函数和 `step()`。

#### `result()`

- 输出：`summary()` 加完整统计历史、帧 CSV 路径和统计 CSV 路径。
- 调用者：`distributed_runtime.get_result()/finalize()`。

#### `summary()`

- 输出：任务键、区域、步号、时间、各生命周期 UAV 数量、等待 handoff 数量和规划
  失败列表。
- 调用者：distributed_runtime 的初始化、入区、查询接口。

#### `close()`

- 输出：无；关闭 CSV。
- 调用者：`distributed_runtime.finalize()`。
