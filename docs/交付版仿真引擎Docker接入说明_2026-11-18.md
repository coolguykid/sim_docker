# 交付版仿真引擎 Docker 接入说明

## 改造结论

区域 DT 的业务链和容器职责没有变化。本次只替换区域容器内部的仿真内核：

```text
POST 导引（稀疏矩阵 P）
  → workflow 加载数据库路网和 UAV 快照
  → routing_planning_input_adapter 将本区实时路网转成交付版 RegionMap
  → 中心全局图提供 PortalSummary 和最终目的地描述
  → local_session 调用交付版完整 centralized_regional、RegionalControl、advance
  → 输出本区 uav_states.csv 和路段统计
  → 协调器转发 handoff
  → 目标区域在收到事件后才规划本区路径并继续推进
```

交付包中的 GUI、随机需求生成、`metropolis_config`、内部导引求解器和演示
调度器没有进入区域 DT 正式执行链。

## 源码变化

- `region_image/Dockerfile`
  - 镜像改为复制 `无人机_大都会36区_导引版/src/uav_sim`。
  - 不再把 `无人机_仅算法1 - 副本` 复制进正式区域镜像。
- `simulation_engine/routing_planning_input_adapter.py`
  - 将数据库节点、管道、真实 Lane、匝道和共享节点 portal 转为交付版
    `PartitionGraph`。
  - 保留数据库 Pipe/Ramp/Lane/Node ID，另外提供现有统计模块所需的只读视图。
  - `build_global_partition_graph()` 用各区域汇总路网构造全局
    `PartitionGraph`，在数据库共享节点之间生成定向 `BOUNDARY` 边。
  - `overlay_local_region()` 在每次尝试开始时用本轮有效本区路网覆盖中心图中的
    本区部分。因此航路调整后的开关、速度和可达性会进入新的 portal 摘要，其他
    区域仍使用中心汇总图。
  - `graph_to_dict()/graph_from_dict()` 负责中心图的 HTTP/JSON 传输。
  - `guidance_transitions()` 建立边到导引单元的映射。`guidance_penalties()`
    按 `-w*ln(max(P,1e-6))` 计算附加边代价，供交付版 `PartitionMaps` 使用。
- `simulation_engine/delivered_uav.py`
  - 保存交付版 `RoadState`，把已认证的 `PreparedMotion` 原子提交为下一状态。
  - 只提供 CSV 和统计层需要的兼容属性，不实现运动算法。
- `simulation_engine/local_session.py`
  - 使用交付版 `RegionalRoutingBackend`，固定
    `mode="centralized_regional", use_ray=False`。`_plan()` 只向官方后端提交
    当前边终点和最终目的节点，由官方 `RegionalDijkstra` 根据全局摘要选择
    portal 并返回当前区域前缀；适配层不再拥有候选 portal 选择逻辑。
  - UAV 已在某条边中间时，当前物理边作为不可变前缀，官方规划从该边终点开始。
  - 使用交付版 `RegionalControl.compute()` 和其内部
    `partition_motion.advance()` 推进每一步。
  - 到达共享节点时输出精确 `crossing_time`、`remaining_step_time` 和 handoff；
    目标区域收到事件后重新规划本区路径。
- `simulation_engine/csv_output.py`
  - `uav_states.csv` 现在保留实际 `node_id`，不再固定输出 `-1`。

## 导引 P 的接口形式

HTTP 请求中的 `global_guidance_transfers` 是全局矩阵 P 的稀疏行表示：

```json
{
  "source_region_id": 1,
  "source_layer": 1,
  "target_region_id": 2,
  "target_layer": 1,
  "proportion": 0.7
}
```

同一 `(source_region_id, source_layer)` 的概率和必须为 1。请求完整保存在区域
服务任务记录中，
本次推演会话读取该固定版本；网络调整后的重推仍使用同一 P。

`global_routing_graph` 是中心全局图的临时内嵌传输字段。正式中心 DT 上线后，
可以改为按 `global_graph_version` 获取/缓存；当前内嵌方式优先用于验证功能。

## 当前边界

- 当前协调器仍以 1 秒屏障转发事件。CSV 中已经保存精确跨界时刻和剩余时间，
  但目标容器会在下一屏障接收；若要求同一秒内继续消耗剩余时间，需要后续把协调器
  改为严格事件子步调度。
- 正式数据库 UAV 快照目前只有目标坐标，没有明确的 `destination_region_id` 和
  `destination_node_id`。跨区正式任务应补充这两个字段或由中心任务接口一并下发；
  当前分布式测试请求已经显式提供。
- 临时方式把约 8.48 MiB 全局图随每个区域请求重复发送并保存，不适合正式 35 区
  高频下发。正式实现应由中心 DT 发布带版本的只读全局图，区域端按版本缓存。
