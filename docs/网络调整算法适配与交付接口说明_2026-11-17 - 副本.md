# 网络调整算法适配与交付接口说明

更新日期：2026-11-18（Asia/Shanghai）

## 1. 文档目的

本文说明航道容量项目中的 `Controller` 如何接入区域 DT Docker 工作流，包括：

- 数据库路网如何适配为算法定义的 `Network`；
- `Controller.step()` 的输入口径；
- 当前调整结果如何转换为 `pipe_status` 和 `ramp_status`；
- 漏斗引路的排除规则；
- 航路调整算法小组后续应交付的最小模块及稳定接口。

## 2. 职责边界

### 2.1 区域 DT 框架负责

1. 从 PostgreSQL 加载指定时刻、指定拓扑版本的路网快照；
2. 加载本轮推演使用的 UAV 初始快照；
3. 运行区域仿真并保存 UAV 帧和路段统计；
4. 判断是否出现需要网络调整的严重拥堵；
5. 将当前有效内存路网转换成调整算法的 `Network`；
6. 将调用时刻前完整 60 秒统计转换成 `passed` 和 `counts`；
7. 调用网络调整算法；
8. 将调整结果临时作用于内存路网并重新推演；
9. 推演通过后，将最终状态写入 `pipe_status` 和 `ramp_status`；
10. 负责跨区域推演协调、Portal 和 Handoff，不由网络调整算法处理。

### 2.2 网络调整算法负责

1. 自行定义并维护 `Config`；
2. 自行定义并维护 `ThroughputModel`；
3. 根据传入的 `Network`、`passed`、`counts` 执行容量控制；
4. 完成管道调速、普通 Ramp 开关、备用管道组启闭；
5. 输出本次控制事件和明确的最终修改结果；
6. 不访问数据库；
7. 不启动仿真；
8. 不负责 UAV 运动、路径规划或跨区域移交；
9. 不负责把结果正式提交数据库。

## 3. 当前接入链路

```text
收到中心导引
  -> 加载数据库原始路网和 UAV 快照
  -> 使用当前有效内存路网进行推演
  -> 每 5 秒输出一次 60 秒滑动窗口统计
  -> 拥堵评价决定需要网络调整
  -> 选择触发时刻对应的完整 60 秒统计窗口
  -> DatabaseControlNetworkAdapter.build_network()
  -> 构造算法 Network、PairLayout、SplitNode、incoming
  -> window_out_count 转为 passed
  -> instant_uav_count 转为 counts
  -> Controller(network).step(time_s, passed, counts=counts)
  -> 比较控制前后的 Network
  -> 生成 pipes/ramps 状态修改
  -> 修改当前有效内存路网
  -> 使用相同 UAV 初始快照重新推演
  -> 推演通过后写数据库并下发导引
```

当前接入文件：

| 文件 | 作用 |
| --- | --- |
| `region_service/network_adjustment_adapter.py` | 数据库路网与调整算法 `Network` 的双向适配 |
| `region_service/integration_ports.py` | 暴露 `invoke_network_adjustment()` 正式调用入口 |
| `region_service/workflow.py` | 在评价不通过后调用网络调整并合并累计修改 |
| `region_service/topology_adjustments.py` | 将修改临时作用于内存快照，最终通过后写数据库 |
| `region_image/Dockerfile` | 将当前算法最小运行包复制进区域镜像 |
| `test/test_network_adjustment_adapter.py` | 网络调整适配和调用测试 |

## 4. `Controller.step()` 当前输入形式

### 4.1 创建控制器

```python
controller = Controller(network)
```

`network` 是算法定义的可变 `Network` 对象。控制器会直接修改其中的：

- `Pipe.speed_mps`；
- `Pipe.is_open`；
- `Ramp.congestion_blocked`；
- `PairLayout.selected_pair_ids`；
- `PairLayout.extra_pairs`；
- `Network.retained_pair_ids`；
- `Segment.passed`；
- `Segment.count`。

### 4.2 调用签名

当前原始签名为：

```python
def step(
    self,
    time_s: float,
    passed: dict[str, float],
    *,
    counts: dict[str, int] | None = None,
) -> list[Event]:
    ...
```

调用示例：

```python
events = controller.step(
    time_s=465.0,
    passed={
        "segment:1:3:100": 7.0,
        "segment:1:3:101": 4.0,
    },
    counts={
        "segment:1:3:100": 12,
        "segment:1:3:101": 3,
    },
)
```

### 4.3 `time_s`

- 类型：`float`；
- 单位：仿真秒；
- 表示决定调用网络调整的仿真时刻；
- 必须有限、非负；
- 对同一个 `Controller` 实例必须严格递增。

例如在 465 秒发现拥堵持续时间达到阈值：

```text
time_s = 465.0
统计窗口 = (405s, 465s]
```

### 4.4 `passed`

类型：

```python
dict[segment_id, float]
```

含义：

> 调用时刻前完整 60 秒内，实际离开该管道 Segment 的 UAV 架次。

来源：

```python
passed[segment_id] = edge_statistics["window_out_count"]
```

注意：

- 不是 `out_flow_per_minute`；
- 不是当前段内数量；
- 不是窗口平均数量；
- 未传入的 Segment 在原控制器中按 0 处理；
- 值必须为有限非负整数或浮点数。

### 4.5 `counts`

类型：

```python
dict[segment_id, int]
```

含义：

> 调用时刻这一瞬间，当前仍位于该管道 Segment 内的 UAV 数量。

来源：

```python
counts[segment_id] = edge_statistics["instant_uav_count"]
```

用途：

- 保护仍有 UAV 的管道组，避免直接关闭；
- 辅助缩容和 retained 管道判断。

值必须为非负整数。传入 `counts` 后，字典中缺失的 Segment 按 0 处理。

### 4.6 统计窗口选择规则

1. 只能使用 `warmup=False` 的完整窗口；
2. 默认窗口长度为 60 秒；
3. 优先使用严重拥堵达到持续时间阈值时对应的统计批次；
4. 如果没有明确触发时刻，使用最后一个完整窗口；
5. 不把多个 5 秒统计值简单相加；每一批本身已经表示过去 60 秒滑动窗口。

## 5. 控制相关 `Network` 字段及来源

| 算法字段 | 来源 | 构造方式 |
| --- | --- | --- |
| `config` | 算法模块 | 算法小组预先定义，不从数据库加载 |
| `throughput_model` | 算法模块 | 算法小组预先定义，不从数据库加载 |
| `layers` | `layer_info`/`pipe_info` | 直接读取或按 Pipe 的 `layer_id` 汇总 |
| `segments` | `pipe_info` | 每条区域局部 `pipe_info` 对应一个 Segment |
| `pipes` | `pipe_info.main_pipe_id` | 相同 `main_pipe_id` 的本地 Segment 组成一条算法 Pipe |
| `regions` | 当前区域 ID | 当前区域包含本地全部 Segment |
| `pairs` | 当前临时推导 | 同层内 `main_pipe_id` 排序后相邻两根组成临时 Pair |
| `ramps` | `ramp_info/ramp_status` | 普通 Ramp 通过起终节点关联唯一入管道和出管道 |
| `incoming` | Pipe/Ramp 节点关系 | 将 Ramp 加入目标 Segment 的进入 Ramp 列表 |
| `layouts` | 动态构造 | 按区域、层、主用/备用、当前开关构造 |
| `split_nodes` | 动态构造 | 按管道组横向位置递归选择间隙中点 |
| `manual_pair_ids` | 动态构造 | 当前开放但不属于布局树引用的管道组 |
| `retained_pair_ids` | 算法运行状态 | 当前兼容接入初始为空；完整缩容时需持续保留 |
| `continuations` | 不需要 | `control.py` 不使用该字段 |

### 5.1 当前临时 Pair 规则

数据库尚无 `main_pipe_pair_id`。当前仅为保证算法可调用，采用：

```text
同一 layer 内按 main_pipe_id 升序排列，相邻两根组成一个临时 PipePair。
```

例如：

```text
main_pipe 1、2 -> derived:L1:G1
main_pipe 3、4 -> derived:L1:G2
main_pipe 5、6 -> derived:L1:G3
```

这是临时兼容规则，不应被解释为最终业务上的正反向配对。以后数据库提供正式的联合启闭组字段后，只替换适配器的 Pair 构造函数。

### 5.2 SplitNode

`SplitNode` 不存数据库。适配器根据以下数据动态生成：

- `layer_id`；
- 层角度；
- 管道几何位置；
- PipePair 横向偏移；
- 主用/备用类型；
- 当前开放状态。

它只表示备用管道组的递归启用顺序，不是飞行路网节点。

### 5.3 Ramp 规则

普通 Ramp 按以下结构适配：

```text
一条入管道 -> 一条 Ramp -> 一条出管道
```

关系：

```text
source_pipe.end_node_id == ramp.start_node_id
ramp.end_node_id == target_pipe.start_node_id
```

### 5.4 漏斗引路排除规则

`ramp_info.type=2` 的漏斗引路不进入网络调整 `Network`：

- 不加入 `Network.ramps`；
- 不加入任何 Segment 的 `incoming`；
- `Controller` 无法关闭或重开漏斗引路；
- 不会出现在调整结果的 `ramp_status` 中；
- 漏斗引路仍保留在实际仿真路网中参与 UAV 运动。

这样可以避免关闭漏斗引路后出现汇入或汇出失败。

## 6. 当前 `step()` 输出及适配方式

原算法当前返回：

```python
list[Event]
```

`Event` 结构：

```python
@dataclass
class Event:
    time_s: float
    region_id: str
    segment_id: str
    action: str
    details: dict
```

但事件不是数据库写入结果：

- `ramps_closed` 原来只包含数量；
- `pairs_expanded` 返回算法 Pair ID；
- 一个算法 Pipe 可能对应多条数据库 `pipe_info` Segment；
- 数据库需要最终状态，不应写入算法的中间操作过程。

因此当前兼容适配器采用：

```text
复制调整前 Network
  -> 调用 Controller.step()
  -> 比较调整前后 Pipe.is_open/Pipe.speed_mps
  -> 比较调整前后 Ramp.enabled/congestion_blocked
  -> 展开到数据库 pipe_id/ramp_id
  -> 生成 pipes/ramps 修改列表
```

当前适配器输出：

```json
{
  "pipes": [
    {
      "pipe_id": 101,
      "speed_limit": 14.86
    },
    {
      "pipe_id": 102,
      "is_open": true
    }
  ],
  "ramps": [
    {
      "ramp_id": 31,
      "is_open": false
    }
  ],
  "control": {
    "time_s": 465.0,
    "window_seconds": 60.0,
    "events": []
  }
}
```

`pipes` 采用部分更新（PATCH）语义：

- `pipe_id` 是数据库 `pipe_info.pipe_id`，始终存在；
- 只有 `Pipe.is_open` 确实变化时才包含 `is_open`；
- 只有 `Pipe.speed_mps` 确实变化时才包含 `speed_limit`；
- 同一次调整中两个字段都变化时可以同时出现；
- 当前算法不修改 `d_safe` 和 `max_capacity`，因此调整结果不得携带这两个字段；
- 未出现在一条修改记录中的字段保持原值，不能解释为默认值或空值。

`ramps` 同样采用部分更新语义；当前算法对 Ramp 只控制开关，因此记录仅包含 `ramp_id` 和实际变化后的 `is_open`。

该输出只临时修改内存路网。合并多轮调整时按字段覆盖，未提供的字段继续保留原值。最终推演通过后，由区域 DT 框架从最终有效路网补齐数据库状态、补充提交时间并写入：

```text
pipe_status(time, region_id, version_id, pipe_id,
            is_open, d_safe, speed_limit, max_capacity)

ramp_status(time, region_id, version_id, ramp_id, is_open)
```

## 7. 网络调整算法小组后续应提供什么

以后不再要求对方提供整个“航道容量项目代码”源码目录。对方应提供一个版本化、可安装、无数据库依赖的最小算法包。

### 7.1 推荐交付物

提供最小源码包：

```text
airway/
├── __init__.py
├── control.py
├── model.py
├── defaults.py          # 可选，保存固定Config/ThroughputModel
└── VERSION
```

如果 `model.py` 的必要运行逻辑依赖其他文件，可随包提供，但不得包含无关系统。

### 7.2 必须包含

1. `Controller`；
2. `Network` 及控制器直接或间接使用的数据类；
3. `Config` 和默认参数；
4. `ThroughputModel` 和默认参数；
5. `Event`；
6. 稳定的 `Controller.step()` 接口；
7. 包版本号；
8. 依赖说明；
9. 最小调用示例；
10. 接口契约测试。

### 7.3 不需要提供

- 网络生成器 `builder.py`；
- UAV 生成器；
- 单机运动仿真；
- 路径规划算法；
- 前端页面；
- HTML/SVG 可视化；
- 演示输出文件；
- 大规模仿真结果；
- MATLAB 对照项目；
- Docker Compose；
- PostgreSQL 操作代码；
- 整个原项目仓库。

### 7.4 算法包不得执行的操作

- 不建立数据库连接；
- 不读取 CSV；
- 不写 `pipe_status/ramp_status`；
- 不修改区域 DT 工作流状态；
- 不调用协调器；
- 不处理跨区域 Handoff；
- 不启动新进程或线程；
- 不自行加载仿真快照。

## 8. 正式输出接口要求

当前采用并保留兼容方案：算法包的 `Controller.step()` 原地修改 `Network` 并返回 `list[Event]`；区域 DT 适配器比较调用前后的状态，输出数据库对象的部分更新。算法小组无需为了区域 DT 修改现有 `step()` 返回类型。

### 8.1 Pipe 部分更新

```text
PipeAdjustment = {
    "pipe_id": int,             # 必填，数据库 pipe_info.pipe_id
    "is_open"?: bool,           # 仅开关实际变化时提供
    "speed_limit"?: float       # 仅速度实际变化时提供，单位 m/s
}
```

要求：

- 只返回发生变化的数据库 Pipe Segment；
- 每个 `pipe_id` 最多一条，多个变化字段合并在同一条记录中；
- 至少包含 `is_open` 或 `speed_limit` 之一；
- 不得附带本次没有发生变化的字段；
- 当前控制器没有修改 `d_safe`、`max_capacity`，不得将其复制到调整结果；
- 一根算法 Pipe 发生变化时，适配器展开其关联的全部数据库 Segment；
- 不返回数据库提交时间，也不直接写数据库。

### 8.2 Ramp 部分更新

```text
RampAdjustment = {
    "ramp_id": int,             # 必填，数据库 ramp_info.ramp_id
    "is_open": bool             # 当前唯一受控字段
}
```

要求：

- 只返回开关发生变化的普通 Ramp；
- 每个 `ramp_id` 最多一条；
- 不得返回 `type=2` 的漏斗引路；
- `is_open` 表示 Ramp 自身调整后的状态，不应仅因为相连 Pipe 关闭就将 Ramp 写成关闭。

### 8.3 事件与数据库完整状态

- `Event` 继续放在 `control.events` 中，仅用于解释、日志和追踪，不作为数据库修改指令；
- 部分更新先合并到初始快照的内存副本，作为下一轮推演输入；
- 只有推演最终通过后，区域 DT 才从最终有效快照读取完整的 `is_open/d_safe/speed_limit/max_capacity` 状态并写入状态表；
- 因此部分更新不会把未修改字段写成默认值，也不会丢失数据库原值。
