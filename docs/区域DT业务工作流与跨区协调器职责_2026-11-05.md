# 区域 DT 业务工作流与跨区协调器职责

## 1. 最终职责划分

### 区域 DT 是业务核心

每个区域 DT 独立负责：

1. 接收中心 DT 下发的本区域导引。
2. 持久化导引请求。
3. 收到导引后才加载本区域路网和 UAV 快照。
4. 保存第一次加载的不可变初始快照。
5. 用初始快照、导引和临时路网调整创建本地区域推演会话。
6. 每秒推进本区域 UAV，并把每一帧写入本区域 CSV。
7. 用本区域统计器计算 Pipe/Ramp 滑动窗口指标。
8. 根据本区域统计判断严重拥堵。
9. 必要时调用航路调整接口。
10. 把调整结果应用到第一次加载的内存快照，重新推演。
11. 所有区域推演通过后，才把本区域调整正式写入数据库。
12. 向运行子系统下发导引，并携带路网是否发生变化及变化内容。

### 协调器只是分布式推演工具

协调器只负责：

- 登记同一个 `run_id/attempt_id` 下已准备好的区域。
- 等待参与区域全部准备完成。
- 向所有区域发送相同的 `step_index/sim_time`。
- 等待当前步所有区域返回，形成同步屏障。
- 按 `to_region` 转发 handoff 事件。
- 统计完成步数和转发事件数。
- 收集各区域的评价结论，形成“全部通过/需要统一重跑”的同步信号。

协调器不读取数据库，不加载路网和 UAV，不接收或解释导引，不计算交通
指标，不判断拥堵，不调用航路调整，不提交路网变化，也不下发导引。

## 2. 当前完整执行链

```text
中心DT
  -> 分别向参与区域 POST /api/v1/guidance

每个区域 workflow.py
  -> load_snapshot()，只执行一次
  -> 保存 original_snapshot
  -> 将数据库 UAV 或 simulation_uavs 转成引擎任务
  -> 将累计临时调整应用到 original_snapshot 的副本
  -> 创建 LocalSimulationSession
  -> 向协调器登记 ready

协调器
  -> 等待全部区域 ready
  -> 并行 step(0)
  -> 等待全部区域返回
  -> 转发 handoff
  -> 并行 step(1)
  -> ...
  -> 达到 horizon，标记 simulation_completed

每个区域 workflow.py
  -> 读取本区域 statistics_history
  -> evaluate_statistics()
  -> 向协调器报告 acceptable/adjustment_required

协调器
  -> 仅等待所有区域报告
  -> 全部 acceptable：collective_decision=acceptable
  -> 任一区域 adjustment_required：collective_decision=rerun_required

区域 workflow.py
  -> acceptable：提交累计路网调整到本区域数据库
  -> dispatch_guidance()，同时通知 topology_changed
  -> rerun_required：需要调整的区域调用 invoke_network_adjustment()
  -> 所有区域从相同 original_snapshot 创建下一 attempt
```

## 3. 相同初始快照重推演

`workflow.run_workflow()` 只在进入任务时调用一次 `load_snapshot()`：

```python
original_snapshot = load_snapshot(request)
```

每轮推演使用：

```python
effective_snapshot = apply_to_snapshot(
    original_snapshot,
    cumulative_adjustments,
)
```

因此上一轮推演产生的 UAV 位置不会成为下一轮初始状态。所有轮次的初始 UAV、
初始路网状态和 `snapshot_time` 一致，只有累计的临时路网调整不同。

临时调整结构：

```json
{
  "pipes": [
    {
      "pipe_id": 12,
      "is_open": true,
      "speed_limit": 40.0,
      "d_safe": 80.0,
      "max_capacity": 50
    }
  ],
  "ramps": [
    {"ramp_id": 5, "is_open": true}
  ]
}
```

调整算法尚未提供时，`invoke_network_adjustment()` 是明确的等待接入接口。

## 4. 通过后提交与下发

只有协调器返回 `collective_decision=acceptable` 后，区域工作流才调用：

```python
commit_to_database(...)
dispatch_guidance(...)
```

动态状态写入：

- Pipe 开关、速度、安全距离、容量写入 `pipe_status`。
- Ramp 开关写入 `ramp_status`。
- 没有调整时不写数据库，`topology_changed=false`。

下发给运行子系统的消息包含：

```json
{
  "guidance": {"transfers": []},
  "topology_changed": true,
  "topology_change": {
    "changed_at": "...",
    "pipes": 1,
    "ramps": 1
  },
  "topology_adjustments": {}
}
```

运行子系统接口尚未提供，因此当前通过后的工作流停在
`waiting_guidance_dispatch`，不会伪造下发成功。

## 5. 区域内 CSV

每个区域、每个 attempt 单独保存：

```text
output/region_XX/<run_id>/attempt_NNN/uav_states.csv
output/region_XX/<run_id>/attempt_NNN/edge_statistics.csv
```

`uav_states.csv` 从 `t=0` 开始保存每一帧，字段顺序固定为：

```text
time,uav_id,region_id,topology_version,active,departed,arrived,edge_type,node_id,pipe_id,ramp_id,lane_id,distance,edge_length,current_speed,x,y,z,acceleration
```

其中 `edge_type=0` 表示 Pipe、`edge_type=1` 表示 Ramp。飞行器位于 Pipe
时 `ramp_id=-1`，位于 Ramp 时 `pipe_id/lane_id=-1`；当前实现的运动状态都在
Edge 上，因此 `node_id=-1`。`active/departed/arrived` 使用 `0/1` 输出。

`edge_statistics.csv` 每 5 秒保存一次 30 秒滑动窗口统计，包括：

- 瞬时与窗口平均 UAV 数量。
- 瞬时与窗口空间平均速度。
- 流入量、流出量和架/min 流率。
- 整条路段和平均每 Lane 密度。
- 速度限制和最大容量。
- 预热标志。

## 6. 拥堵评价

当前内置的是可配置基础规则：

```text
窗口平均UAV数量 / max_capacity >= capacity_ratio
并且
窗口空间平均速度 / speed_limit <= speed_ratio
并且持续时间 >= duration_seconds
```

默认值：

```text
capacity_ratio = 0.8
speed_ratio = 0.5
duration_seconds = 15s
```

任一规划失败也会要求调整。后续确定正式严重拥堵标准后，只需替换
`evaluate_statistics()`，不改变工作流和协调器。

## 7. 主要源码

### 区域业务层

| 文件 | 主要职责 |
| --- | --- |
| `region_service/workflow.py` | 完整区域业务工作流 |
| `region_service/snapshot_loader.py` | 收到导引后加载本区路网/UAV快照 |
| `region_service/distributed_runtime.py` | 保存本区 attempt 的有状态会话 |
| `region_service/coordinator_client.py` | 注册协调器、等待完成、报告评价 |
| `region_service/integration_ports.py` | 评价、调整算法、运行系统下发接口 |
| `region_service/topology_adjustments.py` | 内存应用、累计合并、通过后数据库提交 |
| `region_service/app.py` | 导引入口、协调器 step/handoff 接口、状态查询 |

### 区域仿真层

| 文件 | 主要职责 |
| --- | --- |
| `simulation_engine/local_session.py` | 单区域规划、推进、handoff产生/接收 |
| `simulation_engine/statistics.py` | 本区域 Pipe/Ramp 滑动统计 |
| `simulation_engine/csv_output.py` | 本区域逐帧和统计 CSV |

### 纯协调工具

| 文件 | 主要职责 |
| --- | --- |
| `coordinator_service/app.py` | 区域注册、同步 step 屏障、handoff 转发、评价同步 |
