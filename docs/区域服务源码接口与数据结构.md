# 区域服务源码接口与数据结构

区域服务接收中心导引，读取区域快照，登记各轮推演，评估拥堵并发起航路调整，同时提供任务查询和按轮回放接口。区域以 R02 为例，运行标识为 run-001，导引尝试编号为 0，后续推演尝试可用 1。示例中的 at 表示带时区的观测时刻。

任务状态和事件保存在数据库。各轮的飞行器状态与边统计保存在 CSV，有效拓扑保存在 topology.json。签名里的数据库记录字段可对照建表 SQL。 [数据库结构](../initdb/001_schema_.sql) · [推演引擎接口](区域推演引擎源码接口与数据结构.md)

调用链为 receive_guidance → enqueue_request → worker_loop → execute → run_workflow。在推演期间，协调器请求 finish_distributed_event_frame，区域通过 finish_frame 写帧并检查阈值。回放时，simulation_result_snapshot 调用回放读取器读取对应轮次和时间。

## 文件索引

- `app.py`　FastAPI 区域服务，负责导引入队、状态查询、区域会话 HTTP 入口和 CSV 回放。
- `coordinator_client.py`　区域工作流到协调器的 HTTP 客户端，负责注册轮次、读取进度和上报决策。
- `distributed_runtime.py`　按运行和轮次管理本区域的内存会话。用锁保护帧推进、移交和在线拥堵计数。
- `engine_contract.py`　描述引擎适配契约、输出回调和未接通组件的异常。当前分布式入口由区域会话驱动。
- `integration_ports.py`　在线拥堵评估、容量调整以及导引下发的集成入口。
- `models.py`　区域导引请求及本地、全局转移条目的 Pydantic 模型。
- `network_adjustment_adapter.py`　将数据库快照和路段统计转换为容量控制器的数据结构，再把调整映射回设施 ID。
- `repository.py`　PostgreSQL 访问层，覆盖任务状态、工作流事件、拓扑、设施状态及训练时序。
- `simulation_result_reader.py`　在区域输出目录中索引 CSV 和拓扑归档，按时间读取回放快照。
- `snapshot_loader.py`　导出仓储快照读取函数，并生成写入任务表的快照摘要。
- `topology_adjustments.py`　合并多轮设施调整，并将它们叠加到初始快照的副本。
- `topology_reader.py`　将数据库拓扑或某轮有效快照转换为前端拓扑 JSON。
- `workflow.py`　一条区域导引任务的编排，从读快照、协调推进到评估、调整和再次推演。

## 跨模块数据示例

### 快照与调整

区域仓储读出的快照由 `region_id`、`topology_version`、`snapshot_time`、`network`、`uavs` 组成。`network` 的四个列表是 `nodes`、`pipes`、`ramps`、`lanes`。下面的快照只保留验证开闭变化所需的字段。实际构图时，管道行还需包含起终节点、速度、几何等相应字段。

```python
from topology_adjustments import apply_to_snapshot, merge_adjustments

original = {
    "region_id": 2,
    "topology_version": 7,
    "snapshot_time": "2026-11-25T13:00:00+08:00",
    "network": {
        "nodes": [], "ramps": [], "lanes": [],
        "pipes": [{"pipe_id": 42, "is_open": False, "speed_limit": 10.0}],
    },
    "uavs": [],
}
changes = merge_adjustments(
    {"pipes": [{"pipe_id": 42, "is_open": True}]},
    {"pipes": [{"pipe_id": 42, "speed_limit": 12.0}]},
)
effective = apply_to_snapshot(original, changes)
assert effective["network"]["pipes"][0]["speed_limit"] == 12.0
assert effective["network"]["pipes"][0]["is_open"]
assert original["network"]["pipes"][0]["is_open"] is False
```

### 帧响应与回放响应

协调器结算帧后，区域响应可含 `sim_time=335.0` 与 `congestion={"decision": "adjustment_required", ...}`。此处的时间是仿真时钟。区域服务的回放请求时间可以落在帧之间。例如请求第 120.4 秒，可能返回 `requestedTime=120.4`、`frameTime=120.0`、`statisticsTime=120.0`。响应的 `uavs` 和 `statistics` 分别是无人机状态与路段统计列表。没有统计时 `statisticsTime` 为 null，统计列表为空。

回放拓扑由另一接口返回。先加载 `run-001` 的 `attemptId=1` 的拓扑，再查询同一轮帧，即可使设施开闭和飞行器状态一致。导引任务表中的基础尝试编号可仍然是 0。

## simulation_result_reader.py

在区域输出目录中索引 CSV 和拓扑归档，按时间读取回放快照。

### CsvTimeIndex

单个 CSV 的时间到文件字节位置索引。例如用 uav_states.csv 查第 10 秒全部行。 [源码](../region_service/simulation_result_reader.py#L22)

主要成员为 path、size、scan_offset、header、ranges 和 times。ranges 保存每个采样时刻对应的字节区间，times 保存排序后的采样时间。

#### CsvTimeIndex.__init__

`__init__(self, path: Path)`

为一个按仿真时间组织的 CSV 建立读索引。 [源码](../region_service/simulation_result_reader.py#L25)

- **输入**　path：CSV 文件路径。
- **输出**　None。
- **示例**　传入 Path("uav_states.csv")，随后 rows_exact(10) 可查询第 10 秒。

#### CsvTimeIndex.refresh

`refresh(self) -> None`

增量刷新 CSV 的时间索引。 [源码](../region_service/simulation_result_reader.py#L40)

- **输入**　无显式参数。
- **输出**　None。
- **示例**　uav_states.csv 增加第 10 秒的完整行后，下次查询前增量更新索引。

#### CsvTimeIndex.latest_time

`latest_time(self) -> float | None`

读取当前 CSV 已索引的最新帧时刻。 [源码](../region_service/simulation_result_reader.py#L80)

- **输入**　无显式参数。
- **输出**　仿真秒数或 None。
- **示例**　已有第 0、1、2 秒的输出时得到 2.0，空索引得到 None。

#### CsvTimeIndex.rows_at_or_before

`rows_at_or_before(self, requested: float) -> tuple[float | None, list[dict]]`

找出不晚于请求时刻的最近批次。 [源码](../region_service/simulation_result_reader.py#L91)

- **输入**　requested：请求查询的仿真秒数。
- **输出**　匹配时刻和对应记录列表。
- **示例**　已有第 10、11 秒时，查询 10.8 得到 (10.0, 第 10 秒的行列表)。

#### CsvTimeIndex.rows_exact

`rows_exact(self, requested: float) -> list[dict]`

读取指定时刻的全部记录。 [源码](../region_service/simulation_result_reader.py#L110)

- **输入**　requested：请求查询的仿真秒数。
- **输出**　匹配的 CSV 记录列表。
- **示例**　查询 10.8 且没有该时刻的行时得到 []，查询 10 可得到该秒全部行。
