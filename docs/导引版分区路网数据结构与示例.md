# 导引版分区路网数据结构与示例

`partition_contracts.py` 定义寻路用的数据结构。`partition_graph.py` 将物理空域编译为有向图，再提供区内地图、跨区门户摘要和目的地。寻路器组合这三个视图，返回 `RegionPlan`。 [数据类型](../无人机_大都会36区_导引版/src/uav_sim/airspace/partition_contracts.py) · [图构建与查询](../无人机_大都会36区_导引版/src/uav_sim/airspace/partition_graph.py)

```text
Airspace → compile_partition() → PartitionGraph → PartitionMaps
                                                  ├─ region()      → RegionMap
                                                  ├─ summary()     → PortalSummary
                                                  └─ destination() → Destination
RegionMap + PortalSummary + Destination → RegionalDijkstra.plan() → RegionPlan
```

以下示例使用源码编译器的区域编号 **0、1**。区域 0 的节点 A 到边界门户 X0 有 100 米，区域 1 的边界门户 X1 到目标 G 有 200 米，两段限速均为 10 m/s。X0 和 X1 的坐标相同，以一条有向的零长度边连接。

## partition_contracts.py 中的定义

| 定义 | 字段及含义 | 示例 |
|---|---|---|
| `Vec3` | `Tuple[float, float, float]`，三维坐标或偏移量。 | `(5000.0, 0.0, 135.0)` 表示一个位置。用作偏移时，`(0.0, 3.0, 0.0)` 表示沿第二轴偏移 3 米。 |
| `RoadNode` | `node_id` 是字符串节点键，`region_id` 是所属区域，`position` 是三维位置。`pipe_id` 和 `distance_m` 可为空，分别表示所属管道和沿该管道从起点量起的距离。 | `RoadNode("X0", 0, (5000., 0., 135.), 42, 100.)`。同坐标的 X1 属于区域 1，节点键不同。 |
| `RoadEdge` | `edge_id` 是边键，`source`、`target` 是有向起终点，`region_id` 是边的归属区域。`kind` 区分 `FLY`、`RAMP`、`BOUNDARY`、`GOAL_APPROACH` 和 `CONTINUE` 等边。`length_m`、`speed_limit_mps` 分别以米和米每秒计，`points` 保存几何点。`pipe_id`、`ramp_id` 可关联物理设施。`lane_count` 声明默认值为 20，编译器会显式写入实际值。`offsets_start`、`offsets_end` 按航道下标保存两端相对中心线的偏移，默认空元组。 | `RoadEdge("E0", "A", "X0", 0, "FLY", 100., 10., (a, x), pipe_id=42, lane_count=1)`。边界边 `B` 的起终点为 X0 和 X1，长度为 0，几何为 `(x, x)`。 |
| `PartitionGraph` | `nodes` 和 `edges` 是以字符串 ID 为键的字典。`regions` 保存区域范围，`metadata` 保存编译附加信息，`version` 是拓扑版本，`ramp_states` 按匝道 ID 保存通行状态。后三项默认分别为空字典、0、空字典。 | `graph.edges["B"]` 找到跨区边。若 `graph.ramp_states[7] = False`，从图生成可通行视图时会过滤与匝道 7 关联的边。 |
| `RegionMap` | `region_id` 是详细视图的区域。 `nodes`、`edges` 提供节点与有效边。`adjacency[source]` 是若干 `(target, cost, edge_id)`。 `version` 是拓扑版本，`cost_revision` 是路由代价修订号，两者默认 0。区域视图可包含区外边界目标节点。 | `view.adjacency["A"] == (("X0", 10.0, "E0"),)`。区域 0 的 `view.nodes` 也包含跨区边指向的 X1。 |
| `PortalArc` | `target` 是目标门户，`cost` 是有向代价。`kind` 默认为 `LOCAL`，此时表示区内最短路径的汇总代价。`edge_id` 默认 `None`。跨区弧使用 `BOUNDARY` 并带实际边 ID。 | `PortalArc("X1", 0., "BOUNDARY", "B")`。同区内从门户 M 到门户 N 的最短代价若为 12 秒，可表示为 `PortalArc("N", 12.)`。 |
| `PortalSummary` | `node_regions` 把门户节点映射到所属区域。 `adjacency` 把源门户映射到 `PortalArc` 序列。 `version`、`cost_revision` 对应生成摘要时的图和代价版本，默认 0。 | `summary.node_regions["X1"] == 1`，`summary.adjacency["X0"] == (PortalArc("X1", 0., "BOUNDARY", "B"),)`。 |
| `Destination` | `node_id`、`region_id` 标识目标。`ingress_costs` 保存目标区各可达入口门户到目标的有向最短代价。`version` 和 `cost_revision` 默认 0。`pipe_id` 默认 `None`，`lane_id` 默认 0，`distance_m` 默认 0，`position` 默认 `(0., 0., 0.)`。后三项分别描述目标航道、沿管道距离和三维位置。 | `dest.node_id == "G"`，`dest.ingress_costs == {"X1": 20.0}`，`dest.position == (5200., 0., 135.)`。有航道偏移时，查询会将相应偏移叠加到中心坐标。 |
| `RegionPlan` | `status` 是结果状态。`edge_ids`、`region_path` 默认空元组，分别记录可执行的边序列与计划经过的区域。`cost` 默认正无穷，`version` 默认 0，`reason` 默认空串。当前寻路器返回 `OK`、`NO_ROUTE` 或 `STALE_MAP`。跨区成功时，边序列包含本区前缀和第一条跨区边，代价包含到最终目标的估计总成本。 | `RegionPlan("OK", ("E0", "B"), (0, 1), 30., 7)`。若地图版本不匹配，可返回 `RegionPlan("STALE_MAP", version=7, reason="map and destination versions differ")`。 |

`RoadNode`、`RoadEdge`、`PortalArc`、`Destination` 和 `RegionPlan` 声明为冻结的数据类。冻结限制字段赋值，字段内部对象是否可变仍取决于构造时传入的对象。 [类型定义](../无人机_大都会36区_导引版/src/uav_sim/airspace/partition_contracts.py) · [规划结果构造](../无人机_大都会36区_导引版/src/uav_sim/airspace/partition_router.py)

## partition_graph.py 的模块级定义

| 定义 | 作用及示例 |
|---|---|
| `FrozenDict` | 只读字典，地图视图用它共享数据。读 `FrozenDict({"A": 1})["A"]` 得到 1。它只保护字典本层，视图同时用元组保存邻接弧序列。 |
| `FrozenDict._immutable(*args, **kwargs)` | 写操作共用的异常入口。对上述字典执行 `d["A"] = 2`、`d.update(...)`、`d.pop("A")` 或 `d |= {...}` 都会抛出 `TypeError`。 |
| `FrozenDict.__reduce__()` | 为 pickle 提供重建方式，返回 `(FrozenDict, (dict(self),))`。例如 `pickle.loads(pickle.dumps(d))` 仍是 `FrozenDict`，键 A 对应 1。 |
| `edge_cost(edge)` | 基础代价为 `length_m / max(speed_limit_mps, 1e-12)`。E0 的基础代价是 `100 / 10 = 10` 秒，零长度边 B 的基础代价是 0。 |
| `shortest_paths(adjacency, start)` | Dijkstra 接收按源节点组织的 `(target, cost, edge_id)` 序列，返回 `(distances, previous)`。例如输入 `{"A": (("X0", 10., "E0"),)}` 和 `"A"`，距离为 `{"A": 0., "X0": 10.}`，前驱为 `{"X0": ("A", "E0")}`。按 `previous` 回溯可以取回边 ID。 |
| `_point(value)` | 将坐标序列转成浮点元组。例如 `_point([1, 2, 135]) == (1., 2., 135.)`。 |
| `_lerp(start, end, t)` | 逐分量线性插值。例如 `_lerp((0., 0., 135.), (100., 0., 135.), 0.25)` 得 `(25., 0., 135.)`。 |
| `compile_partition(env, destinations=())` | 从原始空域的范围、管道和匝道编译 `PartitionGraph`。可传入目的地描述，例如 `{"node_id": "G", "pipe_id": 42, "distance_m": 250., "lane_id": 0}`。输入距离须落在管道上，航道下标须有效。 |

### compile_partition 的内部定义

编译器以 5,000 米为网格边长，按 `row * cols + col` 编号，原始 `Airspace` 仍可独立使用。管道的起止点、匝道接入点和目的地附近的锚点先形成切分位置，跨网格边界的几何段再按边界切开。

| 内部函数 | 作用及示例 |
|---|---|
| `owner(position)` | 用坐标计算网格行列，索引钳制到网格范围。若 `xmin=0` 且有两列，横坐标 4,900 和 5,100 分别落在第 0 和第 1 列。移动边归属由该片段的中点决定。 |
| `pipe_node(node_id, pipe, distance)` | 用起点、方向和距离生成管道中心线节点，写入 `nodes` 和按管道组织的 `pipe_nodes`。例如管道 42 的起点登记为 `P42_START`，距离 0。相同 ID 指向不同内容会报错。 |
| `offsets(pipe, distance)` | 计算管道指定里程上每条航道相对中心线的偏移。例如中心线位置为 `(100., 0., 135.)`，某航道位置为 `(100., 3., 135.)`，该航道偏移为 `(0., 3., 0.)`。 |
| `split(...)` | 求线段与网格线的交点参数，创建普通片段与边界边。例中从横坐标 4,900 到 5,200 的正向管段横跨 5,000，生成 100 米和 200 米两个移动片段，中间插入同坐标的零长度跨区边。 |
| `split.interpolated(fraction)` | 在段两端的航道偏移之间插值。例如偏移从 `(0., 0., 0.)` 变到 `(0., 4., 0.)`，参数 0.5 处得到 `(0., 2., 0.)`。 |
| `split.ramp_metadata(name, low, high)` | 有 `ramp_id` 时记录原匝道 ID、方向、片段起止比例及整条匝道的入口、出口偏移。例如匝道 7 的首段可能覆盖 `[0., 0.5]`，方向为 `forward`。 |
| `split.anchor(index, rid, fraction)` | 以 `<edge_id>:C<index>:R<rid>` 创建切分节点。跨界两侧可分别有后缀 `:R0` 和 `:R1` 的节点，坐标相同，各属自己的区域。属于管道时也插值其沿线里程。 |
| `split.boundary(index, left, right, fraction)` | 创建形如 `<edge_id>:B<index>` 的有向 `BOUNDARY` 边，归源区域，长度为零，起止几何点相同。例中的 X0 → X1 由这样的边表示。 |

普通管道片段是 `FLY`。编译器保留 `P42_START`、`P42_END` 等原始节点 ID，里程相同的管道节点可通过零距离的反向别名边相连。物理匝道产生 `RAMP`，双向匝道另外生成反向分支。目的地会生成最长 200 米的 `GOAL_APPROACH`，目标端偏移固定到指定航道，另有零距离离开边接回主线。输入中声明的管道延续关系可生成 `CONTINUE`。

输出图的 `metadata` 包含 `original_pipe_count`、`pipe_endpoints`、`pipes`、`goal_specs`、`ramp_fragments`、`goal_approach_max_length_m`、`region_rows`、`region_cols`、`region_side_length` 和 `bounds`。例如 `pipe_endpoints[42]["start"]` 是 `P42_START`，`goal_specs["G"]["lane_id"]` 是目标航道下标。 [完整编译逻辑](../无人机_大都会36区_导引版/src/uav_sim/airspace/partition_graph.py)

## PartitionMaps 的方法和缓存

| 方法 | 作用及示例 |
|---|---|
| `__init__(graph)` | 建立按区域的节点、边、门户索引及边界边列表，初始化地图、反向邻接、目的地和门户摘要缓存。例中 X0 与 X1 分别进入两区的门户集合。 |
| `_active(edge)` | 判断边是否可用于路由。没有匝道 ID 的边可用。关联匝道 7 且状态为 `False` 时，此边会被过滤。未登记的匝道状态按 `True` 处理。 |
| `with_edge_penalties(penalties, revision)` | 返回共享原图的代价快照，拥有独立的查询缓存。要求修订号为正整数、边存在、附加代价有限且非负。例如 `maps.with_edge_penalties({"E0": 2.}, 1)` 生成修订号 1 的视图。 |
| `_routing_cost(edge)` | 将基础代价和附加代价相加。上述快照中 E0 的代价为 12 秒。 |
| `_check_version()` | 当 `graph.version` 变化时清除已派生的查询缓存。例如切换匝道使版本从 7 变成 8，下次查询会得到版本 8 的视图。此方法保留构造时建立的几何索引。 |
| `region(region_id)` | 返回指定区域的 `RegionMap`，并缓存结果。例中 `region(0)` 只列出归区域 0 的可用边 E0 和 B，同时携带 B 的目标节点 X1。未知区域抛 `KeyError`。 |
| `_local_adjacency(region)` | 从详细邻接中过滤 `BOUNDARY`。在区域 0 的例子中保留 A → X0，X0 → X1 不参与区内 Dijkstra。 |
| `_reverse_adjacency(region_id)` | 反转区内邻接以查询到某点的代价。例如区域 1 的 X1 → G 变为 `reverse["G"] == (("X1", 20., "E1"),)`。反转用于求代价，实际通行方向仍是 X1 → G。 |
| `summary()` | 对各区门户计算可达的区内最短路代价，生成 `LOCAL` 弧，再加入可用的 `BOUNDARY` 弧。例中跨区弧连接 X0 与 X1。返回并缓存 `PortalSummary`。 |
| `destination(node_id)` | 沿目标区的反向邻接从目的地跑一次 Dijkstra，求每个可达入口到目标的代价，读取目的地航道配置和坐标，返回并缓存 `Destination`。例中 `destination("G").ingress_costs["X1"] == 20.`。 |
| `set_ramp_state(ramp_id, enabled)` | 只对已登记的匝道修改状态，变化时递增拓扑版本并使派生视图失效。例如状态 `{7: True}`、版本 7 时调用 `set_ramp_state(7, False)` 返回 8，重复关闭返回 8。未知 ID 抛 `KeyError`。 |

`region()`、`summary()` 和 `destination()` 应来自同一个拓扑版本和代价修订号。`RegionalDijkstra.plan()` 会检查这两项，遇到混用的视图会返回 `STALE_MAP`。 [地图实现](../无人机_大都会36区_导引版/src/uav_sim/airspace/partition_graph.py) · [版本检查](../无人机_大都会36区_导引版/src/uav_sim/airspace/partition_router.py)

## 可运行示例

将导引版的 `src` 加入 Python 模块搜索路径后，可以运行下例，沿着 A → X0 → X1 → G 验证详细地图、摘要、目的地和寻路结果。

```python
from uav_sim.airspace.partition_contracts import PartitionGraph, RoadEdge, RoadNode
from uav_sim.airspace.partition_graph import PartitionMaps
from uav_sim.airspace.partition_router import RegionalDijkstra

a, x, g = (4900., 0., 135.), (5000., 0., 135.), (5200., 0., 135.)
nodes = {
    "A": RoadNode("A", 0, a, 42, 0.),
    "X0": RoadNode("X0", 0, x, 42, 100.),
    "X1": RoadNode("X1", 1, x, 42, 100.),
    "G": RoadNode("G", 1, g, 42, 300.),
}
edges = {
    "E0": RoadEdge("E0", "A", "X0", 0, "FLY", 100., 10., (a, x), pipe_id=42, lane_count=1),
    "B": RoadEdge("B", "X0", "X1", 0, "BOUNDARY", 0., 10., (x, x), pipe_id=42, lane_count=1),
    "E1": RoadEdge("E1", "X1", "G", 1, "FLY", 200., 10., (x, g), pipe_id=42, lane_count=1),
}
graph = PartitionGraph(nodes, edges, {0: {}, 1: {}}, version=7)
maps = PartitionMaps(graph)
region = maps.region(0)
summary = maps.summary()
destination = maps.destination("G")
plan = RegionalDijkstra(summary, region).plan("A", destination)

assert region.adjacency["A"] == (("X0", 10., "E0"),)
assert summary.adjacency["X0"][0].edge_id == "B"
assert destination.ingress_costs == {"X1": 20.}
assert (plan.status, plan.edge_ids, plan.region_path, plan.cost, plan.version) == (
    "OK", ("E0", "B"), (0, 1), 30., 7,
)

weighted = maps.with_edge_penalties({"E0": 2.}, 1)
planner = RegionalDijkstra(weighted.summary(), weighted.region(0))
assert planner.plan("A", weighted.destination("G")).cost == 32.
assert planner.plan("A", destination).status == "STALE_MAP"
```

总成本 30 秒由 E0 的 10 秒、跨区边 B 的 0 秒和目标区入口到 G 的 20 秒相加得到。首段规划只展开 E0 和 B。到达 X1 后，可从区域 1 的详细地图继续规划 E1。

Docker 接入代码另外通过 `build_region_topology()` 从数据库快照构造同一套图类型。本文中 `P42_START`、`:F0` 等命名来自 `compile_partition()`，排查 Docker 结果时应查看适配器生成的节点和边键。 [Docker 图适配](../simulation_engine/routing_planning_input_adapter.py)
