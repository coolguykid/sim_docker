# 区域 DT 层间引路方向与覆盖分析

日期：2026-10-21。依据当前工作区 Markdown 阅读版与 `web-demo/regional.js`，不将 OCR 图中箭头、公式或未核对原件的内容作为确定结论。

后续更新：已按用户要求补齐10条独立下行引路，当前为20条相邻层引路、10上行/10下行。以下方向审计保留为改动前记录；新实现与验证见文末。

## 结论

当前10条层间引路均由低层指向相邻高层，适合作为上行转移示例，但不满足材料描述的完整层间连接要求。单向约束应落实为每条引路只允许一个方向通行，同时配置独立的反向引路，不能据此删去高层到低层的能力。

## 材料依据

- [S3 航路网结构说明书](<../../Markdown材料/S3_低空航路网结构说明书20260802(中国民航大学)_Paddle.md>) §2.2.1（阅读版158、160行）要求每根主干管道与其他各方向层的主干管道直接连接；§2.2.2（164行）重复该要求。文中没有将层间转移限制为低层到高层，也没有限制为相邻层。
- S3 §2.2.3（193–199行）进一步解释：六个方向层时，对某根主干管道有五类其他方向层连接；每类分别配置汇入与汇出接口。再加自由飞与同层反向连接，得到七类、十四个接口。十四是单根管道的接口配置示例，不能直接作为整个区域匝道总数。
- [S7 20260723组会](../../Markdown材料/S7_20260723组会.md) 第1页（10行）明确要求原有双向跨层匝道改为一对单向匝道，且两条匝道连接的管道起终点可以不同。这直接支持分别建设上行、下行连接，而不是允许同一条曲线逆向通行。
- S7 第1页（12行）还要求通行时间约等于连接路径长度除以速度，并在运行前计算长度。现有几何初始化时计算长度、轨迹段按长度/速度计算时长的做法与此方向一致。

## 当前实现核查

`regional.js` 的层间构建循环仅遍历 `l=0…4`，目标层固定为 `l+1`，每层对只选 `p=0、5` 两根代表主干。方向审计通过 Node VM 实际加载源码并检查全部 `kind==='ramp'` 对象的端点与层号，结果如下。

| 项目 | 当前结果 | 与材料的关系 |
| --- | --- | --- |
| 层间引路总数 | 10 | 五对相邻层，每对两条 |
| 上行 / 下行 | 10 / 0 | 缺少下行引路 |
| 非相邻层直连 | 0 | 缺少其他方向层直连 |
| 源管道覆盖 | L1–L5的P01、P06，共10根 | 未覆盖全部60根管道；L6无层间出口 |
| `-R` 后缀 | P06反向水平主干之间的上行连接 | 表示主干水平飞行方向，不表示层间下降 |
| 动画示例 | L1-P01 → X-L1-L2 → L2-P01 | 只演示一条上行转移 |

主干层的高度与方向角绑定，因而仅有上行连接也会限制方向转换：进入高层后，无法通过现有层间图返回低层；绕经相邻层也不等于材料要求的直接连接。

## 后续实现建议与边界

若只补齐现有相邻层代表网络，可新增10条独立下行引路，与原上行形成20条有向连接。这只是补齐当前演示的往返能力，仍不满足所有方向层、所有主干管道的覆盖要求。

若按S3完整建模，应先确定每根源管道在其他方向层的目标管道、开放状态和接口位置，再生成明确的源/目标有向连接。下行引路需要匹配源管道驶出与目标管道驶入方向，并独立布设控制点；不能简单反转同一曲线，也不能将转移时间、相交避让或安全间隔视为已验证。

本次仅调整文字按钮所在工具栏并分析层间逻辑，未修改层间拓扑。汇入/汇出采用用户此前确认的漏斗直达目标层方案；S3中最高层公共主引路的旧描述不改变该已确认方案。
