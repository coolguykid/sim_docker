# 区域 DT 展示评估与黄浩然数据对接草案

日期：2026-10-20。状态：供双方确认的需求草案，不是已同意接口。评估对象为 `web-demo/index.html`，不将 `regional-dt` 工程已有的其他能力算作本 Demo 已实现。

## 1. 结论及证据范围

当前页面适合评审颜色、布局和管道态势交互，部分覆盖最小区域展示需求；不满足完整区域 DT 的功能和数据验收要求。页面全部数据由 `sample()`、`pipesFor()`、`renderMatrix()` 和 `drawTrend()` 等函数生成，尚未读取外部 JSON、数据库或实时推演输出。

不能用“布局和交互测试通过”替代“项目功能完整、数据正确或算法性能通过”。本次不修改 Demo 页面，交付符合性分析和 JSON 样例。

另有三点应先调整展示责任：

1. 区域页仍显示36×6全域热力图，需要中心汇总数据；黄浩然单区域输出无法独自支撑。区域主面板宜改成“本区域层×管道状态”，全域热力图留在中心页或作为中心数据附加面板。
2. 建议/推演/实际转移矩阵不是首批区域核心展示；建议来自符双冀，宏观推演来自张茜琳。实际转移应统计完成事件或明确流率口径，不把匝道在途数量当转移量，不强制所有实际矩阵行和为100%。
3. 现有流量为 `数量×速度×60/3000` 的估算；它不是出口断面实测，更不等于全区吞吐量。全区累加各管道流量可能把同一架无人机在多个管道重复计数。建议区分“管道断面流量”“各管道流量合计”“区域边界完成量”。

## 4. JSON交付方式和现有协议关系

先交付两个UTF-8 JSON文件：

- [regional-topology.example.json](../examples/regional-topology.example.json)：一次初始化的元数据与缩减拓扑。
- [regional-frames.example.json](../examples/regional-frames.example.json)：同一run、同一区域、同一拓扑版本的连续3个输出帧数组。

样例全为本次生成的mock数据，不是黄浩然给出的结果；用于讨论字段和对象引用，不是完整科研场景。第一帧2架都在P1，第二帧1架P1/1架匝道，第三帧1架P1/1架P2，演示跨层时不重复计数。空管道数量为0、均速为null。

后续可将初始化消息及每帧JSON分别作为REST结果或WebSocket消息，不要求数据先入数据库，不限制推演内部类或数组布局。首轮建议完整快照，先不设计增量。

`schemaVersion=regional-simulation-draft-0.1`是新草案标识。不是已有MVP的`1.0`合同，不能直接塞入现有校验器。沿用`regionId`、`topologyVersion`、`uavNumber`、`averageSpeed`、`snapshotId`等命名，但新增run/仿真步/能力与非管道位置表达；接入时需要适配层。当前`web-demo/index.html`也尚未实现JSON导入。

## 5. 公共字段和时间

| 字段 | 规则 |
| --- | --- |
| schemaVersion/type | 协议版本；type为topology或snapshot。 |
| runId | 推演运行唯一ID，重启新实验必须换ID。不能和数据库实时运行批次混淆。 |
| scope.regionId | 字符串，限定区域。拓扑中同名ID需结合区域/版本定位。 |
| topologyVersion | 字符串；帧引用已取得的同版本拓扑。拓扑修改发新版本，不把新状态套旧几何。 |
| streamId/seq | 一次run/区域输出流的标识与安全整数序号；同流递增，不跨流比较。超JS安全整数的标识/版本按字符串。 |
| snapshotId | 唯一帧ID，用于去重和关联。requestId用于请求/日志关联。 |
| step | 非负整数，算法步编号，可因每N步输出而不连续，不等于秒或序号。 |
| simulationTimeSeconds | 从本run起点累计的仿真秒，权威回放时间。变步长不能用step固定换算。 |
| simulationTime | 有时区ISO8601，虚拟仿真起点+累计仿真秒；不是实际生成时间。 |
| sampleTime | 本草案模拟状态的采样时刻，取simulationTime；对接实时数据库时须由适配器重新明确，不能默默混用时钟域。 |
| serverTime | 实际消息生成/发送墙钟UTC时间。离线mock也只是样例值，不能用于测量真实网络时延。 |
| quality | source为mock/simulation/observed之一；真实推演用simulation，实时采集用observed；complete仅表示所声明必需数据完整，missingObjects列出缺失ID。未支持能力不应伪装成0。 |

metadata.simulationClock声明固定步长和每N步输出；实际频率待算法负责人确认。文件帧按仿真时间排序。后续实时完整快照可跳到较新帧恢复状态，但完成转移等累积事件不得静默丢弃。回放必须按实际保留帧播放，不从最新帧伪造历史；存文件也可回放，无需预先决定数据库。

## 6. 初始化data：静态拓扑与能力

`data.metadata`：

- `coordinate`声明局部东/北/上轴、单位、原点标识和高度基准。跨区域需要共同原点或明确变换，不能拿各自局部坐标直接拼接。前端做唯一坐标适配，不把显示展开高度当业务高度。
- `units`声明指标单位；`metricDefinitions`说明具体统计口径。`displayThresholds`由业务方确认后提供，未知为null；前端可用标为示意的展示阈值，不能当拥堵判据。
- `capabilities`逐项声明是否可提供；false指本数据源不支持/未提供，不表示现实中没有该对象。`unavailableReasons`说明原因。

`data.topology`尽量沿用已有MVP结构：

| 对象 | 最小字段与说明 |
| --- | --- |
| 区域 | regionId、versionId、validFrom/validTo、range。range是矩形包围盒，不替代真实边界。 |
| layers | layerId、angle、height；高度单位m、角度deg；angle为+x向东起逆时针朝+y向北。真实输出若不同先转换。 |
| nodes | nodeId、layerId、position[x,y,z]；ID不得依赖数组位置。 |
| pipes | pipeId、layerId、startNodeId/endNodeId、length；type和laneNumber/pipeWidth由拓扑来源给出，不知道时改为可空并说明。方向以起点→终点为准。 |
| ramps | rampId、startNodeId/endNodeId、path连续采样点、length、两端区域；单向连接，反向需要独立几何。长度与路径弧长关系需确认容差。 |
| lanes | laneId、pipeId、startPt/endPt；曲线航道应扩展path。未提供用null，确定没有才用[]。 |
| boundary | 本坐标系的水平多边形顶点；未知null。 |
| noFlyZones | 若提供：zoneId、水平polygon、minHeight/maxHeight、validFrom/validTo；未知null，确认无禁飞区才[]。 |
| freeFlightAreas | 若提供：areaId、水平polygon、minHeight/maxHeight；是否覆盖本次推演先确认，未知null。 |
| funnels | 若提供：funnelId、type(takeoff/landing)、centerXY、bottomHeight/topHeight、bottomRadius/topRadius、连接节点；暂不规定所有算法必须支持此几何。 |

若已有数据库能提供同版本拓扑，只需黄浩然说明引用方式，双方明确谁导出，无需每帧重复所有几何。后续版本变化再发初始化消息。缩减样例的层高/宽度/路径只检验结构，不表示航路规则或安全可行。

## 7. 每帧data.state：先把管道状态做实

| 字段 | 首轮必要性 | 含义/单位/规则 |
| --- | --- | --- |
| pipes[].pipeId | 必需 | 引用初始化管道ID。 |
| pipes[].uavNumber | 必需，可空 | 同一仿真时刻对象内不同UAV数量，架；0表示确认空，null表示未知。 |
| pipes[].averageSpeed | 必需，可空 | 上述有效UAV的瞬时标量速率算术平均，m/s；空管道或无有效样本为null。若只有部分有效速度，需另给有效样本数，不能直接用总数量加权。 |
| pipes[].isOpen | 需要状态展示，可空 | 是否允许按约定规则通行；null未知。关闭可仍有排空飞行器，须区分禁止进入和禁止一切通行。 |
| pipes[].flow | 后续，可空 | 指定断面在窗口内的通过数/时长，架/分钟。提供时额外给flowMethod、sectionId、flowWindow:{fromSimulationSeconds,toSimulationSeconds}，窗口[from,to)。估算必须标estimated。 |
| pipes[].density | 后续，可空 | 架/km；必须给densityBasis:pipeLength或totalLaneLength；本样例尚未确认，全部null。 |
| pipes[].maxCapacity | 后续，可空 | 同时容纳数量，架；不是架/分钟的通行能力。必须说明是否已经考虑开放状态、资源与安全距离。 |
| pipes[].speedLimit/safeDistance | 后续，可空 | m/s、m；提供生效时间或随同版本/帧有效。 |
| ramps | 匝道态势可选 | rampId、isOpen、uavNumber、averageSpeed；不能从在途数量得出完成转移量。未接入返回null。 |
| summary | 可选 | 样例为null，不强求上游重复计算。若提供须声明对象范围、缺失情况及去重规则。 |

完整快照要求每个已知管道都有记录，即使为空。未取得某管道状态时保留ID、指标null，并在quality.missingObjects标记；省略对象不等于删除/关闭。几何对象删除由新拓扑版本表达。

区域/层数量只可对互斥对象集合求和，汇总不能混加管道数与其航道数。区域含匝道/自由飞时，不能只加管道就叫“区域全部数量”。跨层匝道上的UAV应单列“转移中”，不得同时算入两层；若业务采用其他归属规则须显式约定。

利用率只在容量与覆盖范围一致时计算，分母0或缺失为null。区域速度按同一时刻有效UAV加权，不能平均各管道均速；若汇总排除匝道需标注范围。缺少密度/容量时页面禁用对应着色或显示暂无数据，不用mock替代真实结果。

## 8. 个体位置：按需扩展，不以pipeId限制全部阶段

若仅演示管道汇总，`uavs`和`uavCoverage`可为null，不阻塞P0。若要求真实UAV运动，则需要：

| 字段 | 说明 |
| --- | --- |
| uavId | 同run内稳定的字符串ID，跨域不换ID。 |
| regionId | 当前权威区域；边界交接需唯一归属，不能两个区域重复计数。 |
| position | 该帧仿真时刻[x,y,z]，统一坐标与m单位。 |
| speed | 标量速率m/s，可空；如原始速度为向量，应附定义或由服务转换，不猜测分量。 |
| phase | pipe / ramp / freeFlight / takeoff / landing / unknown。 |
| location | {type,objectId}。type可为pipe/ramp/freeFlightArea/funnel/unknown，按type关联对应几何；unknown的objectId为null。 |
| laneId | 可空，仅在确切位于对应航道时填值。 |
| uavCoverage | mode为full/sampled，scope说明返回范围，total/returned说明总数和返回数。抽样位置不能用来反推完整数量。 |

完整快照中没返回的UAV仅表示“不在本帧该范围中”，不能据此认定已抵达；抵达、失联和跨域交接若需展示应另给事件/状态。自由飞阶段没有pipeId，不能强行绑定最近管道。当前已有MVP的UAV必需pipeId结构需适配，本草案使用location表达。

本缩减样例给出完整2架位置，故允许校验管道/匝道计数与均速；真实数据若位置抽样或未提供，仍使用完整汇总统计。位置插值仅在同run、同版本、同UAV且连续合理时间间隔中执行；不能用线性连接替代未提供的规划路径。

## 9. 后续可选模块：明确提供人，缺失保持null

- `predictions`：predictionId、issuedAtSimulationSeconds、method、horizonSeconds、objectAxis、timeAxisSimulationSeconds、metric、unit、result。必须标明对象×时间，不能要求所有模型固定15分钟；与推演当前状态分开。预测误差要等对应真值到达后评价。
- `strategies`：strategyId、算法版本、type、target、proposed/effective等状态、生效区间、reason。黄浩然可转发关联结果，不承担符双冀中心策略生成。执行状态由执行方反馈，不从模拟备用开关反推。
- `performance`：若采集则给computeTimeMs及覆盖的仿真时间区间/步数；实时倍率=覆盖仿真秒/对应墙钟耗时秒，说明是否含初始化/I/O。碰撞/近距越界/完成率/延误需定义、观察窗口和来源，没统计用null，不是0。FPS/渲染耗时由前端自身采集。
- 完成转移：eventId、uavId、fromLayerId、toLayerId、rampId、completedAtSimulationSeconds；仅有管道汇总和每步位置未必能完整恢复跨步事件。
- 自由飞/起降：确认算法覆盖后再启用能力并提供几何、阶段、位置和流入/流出；没有这些数据不能宣称全任务展示完成。

以上扩展字段结构需对应负责人确认，首轮不要求所有成员尚未实现的模块都交给黄浩然补齐。

## 10. 先请黄浩然确认的8项

1. 首轮能否提供一个区域、同一run/版本的拓扑或拓扑引用，以及连续3个以上输出帧？
2. 数量/均速是否按管道、同一时刻统计？速度单位、标量含义、空管道规则是什么？
3. 仿真step与仿真秒关系、输出间隔是多少？本草案0.5秒/4步仅示例。
