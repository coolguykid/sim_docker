# Docker 区域 DT 数据接入前端说明

日期：2026-11-13  
范围：仅说明 `dt-web-demo` 文件夹内为接入 Docker 区域 DT 数据所做的修改，不说明 `region_service`、`simulation_engine`、协调器、数据库或 Docker Compose 内部实现。

## 1. 本次修改目标

原区域 DT 页面使用浏览器本地生成的离线演示路网、UAV 和性能数据。本次修改在保留原离线演示的基础上，使页面能够：

1. 从各区域 Docker 服务读取数据库真实路网。
2. 读取该区域最新一次 DT 推演及其逐帧 UAV 状态。
3. 在推演产生数据时通过 SSE 实时接收，而不是等待整次推演结束。
4. 使用真实管道、匝道、漏斗和 UAV 状态绘制区域场景。
5. 将路段滑动窗口统计接入详情、排序、着色和历史曲线。
6. 切换区域时只订阅当前选中区域，关闭上一个区域的事件流。
7. Docker 数据不可用时保留原离线演示作为回退。

当前接入范围为 R01–R35：

```text
R01 -> http://127.0.0.1:18101
R02 -> http://127.0.0.1:18102
...
R35 -> http://127.0.0.1:18135
```

R36 当前没有对应区域 Docker 服务，继续显示原离线演示。

## 3. 页面脚本加载顺序

`index.html` 新增：

```html
<script src="region-db-topology.js"></script>
<script src="region-simulation-results.js"></script>
<script src="regional.js"></script>
```

顺序不能交换，因为：

- `region-simulation-results.js` 使用 `RegionDbTopology.endpoints` 查找区域服务地址。
- `regional.js` 同时调用 `RegionDbTopology` 和 `RegionSimulationResults`。

这两个适配器都只读数据，不负责下发导引，也不负责启动推演。

## 4. 区域数据库拓扑接入

### 4.1 服务地址配置

`region-db-topology.js` 中的 `endpoints` 建立区域编号与宿主机端口的映射：

```javascript
regionId -> http://127.0.0.1:(18100 + regionId)
```

当前生成 1–35 共35个地址。后续接入区域36时，需要把生成范围扩展到36，并确保区域36容器端口为18136。

### 4.2 请求接口

```http
GET /api/v1/topology
Accept: application/json
```

### 4.3 `validate()`

拓扑进入页面前检查：

1. `schemaVersion` 必须为 `regional-topology-1.0`。
2. 返回的 `regionId` 必须等于当前请求区域。
3. `layers`、`nodes`、`pipes`、`ramps`、`lanes` 必须是数组。
4. 每条管道引用的起点和终点必须存在于节点集合中。

验证失败时不会用不完整数据绘图，而是记录错误并回退到离线演示。

### 4.4 `adapt()`

接口数据被转换为前端绘制和拾取所需结构：

- `nodes` 转为按字符串节点 ID 索引的 `Map`。
- 管道增加唯一键 `pipe:{pipeId}`，几何由起终节点坐标构成。
- 匝道增加唯一键 `ramp:{rampId}`，使用接口返回的路径点。
- 航道增加唯一键 `lane:{laneId}`。
- 管道、匝道、漏斗统一进入 `objects`，用于点击、悬浮和详情查询。
- `type=funnel` 的引路按连通分量和节点类型区分汇入、汇出。
- `nodeType=1/2` 的节点转换为起飞/降落漏斗对象。
- `isPortal=true` 的节点仍保存在 `portals` 中供拓扑语义使用。

共享边界节点目前不在画布、图例、拓扑详情或左上角计数中显示，但数据没有删除，不影响后端 Portal 和跨区域移交。

### 4.5 缓存

每个区域的拓扑请求以 Promise 形式缓存。同一区域重复进入时不会重复加载完整拓扑；请求失败时删除该区域缓存，允许下次重新请求。

## 5. 推演结果接入

`region-simulation-results.js` 封装了三类只读操作。

### 5.1 查询最新推演

```http
GET /api/v1/simulation-results/latest
```

用途：进入某个区域时，获取该区域当前可用的最新 `runId`、`attemptId`、最小时间和最大时间。

### 5.2 按时间读取一帧

```http
GET /api/v1/simulation-results/{runId}/attempts/{attemptId}/snapshot?time={time}
```

用途：

- 拖动时间轴。
- 点击重播或最新时刻。
- 按不同播放倍率进行历史回放。

浏览器只读取请求时刻对应的一帧，不把整个 `uav_states.csv` 和 `edge_statistics.csv` 一次性载入内存。

### 5.3 实时事件流

```http
GET /api/v1/simulation-results/stream
```

使用浏览器 `EventSource` 建立 SSE 连接，支持参数：

```text
run_id
attempt_id
after
```

处理两种事件：

| 事件 | 内容 | 前端处理 |
|---|---|---|
| `run` | 当前推演元信息 | 更新推演编号、轮次和可播放时间范围。 |
| `snapshot` | 新完成的UAV帧和最近统计批次 | 更新地图、详情、排序和曲线。 |

如果出现新的 `runId/attemptId`，前端会清理旧帧、旧统计历史和旧快照键，自动跟随新推演。

## 6. 区域切换与连接生命周期

`regional.js` 为外部数据增加了以下状态：

```text
dbTopology
dbTopologyRegion
dbTopologyLoading
dbTopologyError
dbSelected
dbSimulation
dbSimulationRegion
dbSimulationSnapshot
dbSimulationStream
dbSimulationFollow
dbSimulationStatsHistory
```

切换区域时执行：

```text
关闭上一区域 EventSource
    -> 清理上一区域推演状态和统计历史
    -> 加载新区拓扑
    -> 查询新区最新推演
    -> 请求当前帧
    -> 建立新区 SSE
```

因此选中区域15后，前端只保持区域15的实时事件流，不会同时订阅其余34个区域的完整帧。其他区域容器仍正常推演和写文件，只是不向当前页面持续传输完整帧。

## 7. 真实路网绘制修改

当 `dbTopology` 存在时，`drawScene()` 转入数据库拓扑绘制分支，不再使用离线模拟路网。

### 7.1 管道

- 使用数据库节点坐标确定起点和终点。
- 主用和备用管道沿用离线模式线宽和风格。
- 关闭路段使用低透明度虚线。
- 管道方向用箭头表示。
- 管道端点保留小圆点，但共享边界节点不再单独高亮。
- 选中管道时增加白色外描边。

### 7.2 匝道和引路

- 使用数据库返回的完整路径点。
- 层间上行、层间下行、同层反向连接使用不同颜色和虚线样式。
- 漏斗汇入引路使用紫色实线。
- 漏斗汇出引路使用紫色点划线。
- 开放引路绘制方向箭头。

### 7.3 漏斗

- 使用真实节点和漏斗引路连接关系识别起飞/降落漏斗。
- 继续沿用离线模式的锥台显示参数。
- 漏斗本体和引路都可以点击查看详情。

### 7.4 层筛选和视角

- 数据库 `layers` 决定可显示层。
- 保留离线模式的旋转、缩放和高度展开。
- 单层筛选同时作用于真实管道列表和主干排序。

## 8. UAV帧接入与渲染

实时或回放快照中的 UAV 主要使用：

```text
uavId
active
edgeType
pipeId / rampId
laneId
distance
edgeLength
speed
position[x,y,z]
acceleration
```

绘制规则：

1. 只绘制 `active=true` 且坐标有效的UAV。
2. 根据 `edgeType` 和边ID关联当前数据库路段。
3. 根据路段起终方向计算UAV箭头朝向。
4. 管道、普通匝道、层间匝道和漏斗引路使用对应路段颜色。
5. 所有运行UAV统一使用箭头，不再使用橙色点或黑色点。
6. 当前区域之外的UAV不会出现在该区域快照中。

当前瞬时路段数量由同一帧 `uav_states.csv` 中满足以下条件的UAV重新计数：

```text
active=true
edgeType与路段一致
edgeId与路段一致
```

这保证路段当前数量与画面中实际绘制的UAV一致。

## 9. 路段统计接入

推演快照中的统计数组被转换为：

```javascript
statisticsMap.get(`${edgeType}:${edgeId}`)
```

避免每次刷新都线性扫描所有路段。

当前页面实际使用的 `edge_statistics.csv` 指标包括：

| 字段 | 用途 |
|---|---|
| `time` | 统计时间、历史曲线时间轴。 |
| `edge_type`、`edge_id` | 关联管道或匝道。 |
| `instant_uav_count` | 数量历史曲线；当前瞬时显示仍以UAV帧计数为准。 |
| `window_space_mean_speed` | 路段详情、速度曲线和速度着色。 |
| `out_flow_per_minute` | 路段详情和流量历史曲线。 |
| `window_density_per_km` | 管道详情、密度曲线和密度着色。 |
| `window_min_spacing_m` | 通行约束中的实际最小间距。 |
| `window_max_running_speed` | 通行约束中的实际最高运行速度。 |
| `speed_limit` | 速度上限和约束对比。 |
| `max_capacity` | 容量占用率、主干排序和路段详情。 |

统计采用60秒滑动窗口，每5秒更新。前60秒属于预热期，但当前页面还没有单独显示 `warmup` 标记。

## 10. 页面信息和交互修改

### 10.1 区域顶部指标

数据库推演模式下：

- 当前主干UAV数量来自当前UAV帧。
- 区域平均速度来自当前主干UAV帧。
- 区域容量利用率按当前数量除以开放管道容量计算。
- 暂无真实来源的区域指标继续显示“暂无数据”，不混入离线模拟值。

### 10.2 对象点击和悬浮

数据库对象使用独立键：

```text
pipe:{id}
ramp:{id}
funnel:{nodeId}
```

避免数据库中管道ID和匝道ID相同时冲突。画布悬浮显示对象类型和开放状态；点击后更新详情、历史曲线和通行约束。

### 10.3 管道/匝道详情

详情字段与离线模式保持同一结构，主要包括：

- 区域和层。
- 高度、长度。
- 当前数量。
- 60秒窗口空间平均速度。
- 60秒窗口出口流率。
- 60秒窗口平均密度。
- 最大同时容量。
- 速度上限和安全距离。
- 航道数、管径或匝道宽度。
- 有向连接关系和采样时刻。

最小间距和最高运行速度只用于“通行约束”图，不重复放进点击路段的详情卡。

### 10.4 主干利用率排序

数据库模式下排序范围改为真实管道：

```text
瞬时容量占用率 = 当前UAV帧中的路段数量 / maxCapacity
```

支持：

- 层筛选。
- 主用/备用筛选。
- 开放状态筛选。
- 高负载/低负载筛选。
- 管道编号搜索。
- 点击排序项定位路段。

### 10.5 历史与预测曲线

选中管道或匝道后，可切换：

- 数量。
- 平均速度。
- 出口流量。
- 密度。

当前时间轴为：

```text
过去3分钟：来自区域DT真实统计
未来3分钟：暂时保留离线演示预测
```

真实统计历史保存在浏览器内存中，最多保留400个统计时刻；切换区域或切换到新的推演轮次时清空。

### 10.6 通行约束曲线

接入内容：

- 拓扑安全距离。
- 60秒窗口最小间距。
- 统计速度上限。
- 60秒窗口最高运行速度。

安全距离主要来自拓扑状态，运行最小间距和最高速度来自路段统计。

## 11. 实时跟随与历史回放

页面存在两种状态。

### 11.1 实时跟随

`dbSimulationFollow=true`：

- SSE每收到一帧就更新当前快照。
- 时间轴自动移动到最新仿真时间。
- 不需要等待整次900秒推演完成。

### 11.2 历史回放

用户执行以下操作后退出实时跟随：

- 点击播放。
- 点击重播。
- 拖动时间轴。

页面随后按时间调用单帧接口。点击“最新”会恢复实时跟随。回放取帧不再限制为1倍速，当前选择的播放倍率均可推进时间轴和请求对应帧。

## 12. 数据缺失与回退策略

| 情况 | 页面行为 |
|---|---|
| 区域拓扑加载成功 | 显示数据库真实路网。 |
| 区域拓扑请求失败 | 显示错误信息并回退原离线区域演示。 |
| 有拓扑、没有推演结果 | 显示真实路网，UAV和性能显示暂无数据。 |
| 最新推演存在 | 加载最新帧并建立SSE。 |
| SSE暂时中断 | 显示连接中断提示，浏览器EventSource按机制重连。 |
| 切换区域 | 关闭旧SSE，避免旧区域帧覆盖新区域。 |
| 选择R36 | 清理Docker数据状态，使用离线演示。 |
